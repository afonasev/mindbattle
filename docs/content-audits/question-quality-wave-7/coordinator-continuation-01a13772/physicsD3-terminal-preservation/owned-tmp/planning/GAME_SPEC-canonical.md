# Mindbattle — каноническая спецификация игры

Статус: discovery

Последнее обновление: 2026-09-12

## Назначение документа

Этот документ хранит только утверждённые решения о продукте и игре. Неутверждённые варианты находятся в разделе `Открытые решения` и не являются разрешением на реализацию.

При изменении утверждённого решения сначала обновляется соответствующий раздел и журнал изменений, затем код, тесты и OpenSpec-артефакты.

## Утверждённое видение

- Рабочее название проекта — **Mindbattle**.
- Основной локальный режим — интеллектуальная соревновательная викторина для компании друзей на одном общем экране.
- Игра проверяет широкую эрудицию, скорость воспоминания и способность команды согласовать единый ответ под ограничением времени.
- В партии участвуют от двух до четырёх команд: зелёная, синяя, жёлтая и красная. Состав и число людей внутри команды приложение не фиксирует; команда может состоять из одного человека.
- На каждый вопрос одновременно отвечают все участвующие команды. Выбранный командой ответ скрыт до общего раскрытия.
- Classic-v1 продолжает работать в актуальном desktop Chromium с Node runtime и одним общим экраном. Соло-забег дополнительно поддерживает portrait-телефоны шириной 360–760 CSS-пикселей как устанавливаемая PWA; на таком viewport командная настройка и её запуск временно не показываются. Runtime обслуживает клиент и same-origin API обратной связи; production runtime принимает анонимную запись с любого устройства в единый серверный журнал. Аккаунты, данные устройств, внешняя аналитика, AI, ведущий и зрители не используются. Steam-публикация не входит в первый прототип.

## Структура партии

- В главном меню выбираются:
  - длина партии: 9, 15 по умолчанию или 21 вопрос;
  - число команд: от двух до четырёх;
  - базовое время ответа: 10, 20 по умолчанию или 30 секунд;
  - отдельное устройство или клавиатурная схема управления для каждой команды.
- Партия всегда состоит из трёх этапов одинаковой длины:
  - при 9 вопросах — по 3 вопроса на этап;
  - при 15 вопросах — по 5 вопросов на этап;
  - при 21 вопросе — по 7 вопросов на этап.
- Первый этап использует простые вопросы и даёт 100 очков за верный ответ, второй — средние вопросы и 200 очков, третий — сложные вопросы и 300 очков.
- Последний вопрос каждого этапа является бонусным и даёт удвоенное число очков.
- Баланс партии оформляется именованным профилем `classic-v1`; конкретные значения длины, времени, запаса и очков должны находиться в валидируемой конфигурации правил.

### Соло-забег

- В главном меню доступен отдельный профиль `solo-endless-v1` для одного игрока. В mobile PWA он использует только touch-действия; desktop-поток может принимать pointer, обе клавиатурные схемы и доступный геймпад. Выбор источника не меняет авторитетные правила и результаты `classic-v1`.
- В шапке каждого сыгранного соло-вопроса после его счётчика в скобках показывается назначенная сложность: «Лёгкий», «Средний» или «Сложный». Та же подпись показывается в добровольной форме жалобы из меню паузы; это только представление и не меняет правила забега.
- Забег не имеет конечного числа вопросов. Его авторитетный план слотов: четыре обычных easy-вопроса, пятый рискованный easy-бонус; затем два последовательных блока `3 обычных medium + 1 обычный hard + рискованный medium-бонус`; далее бесконечно повторяется блок `3 обычных medium + 1 обычный hard + рискованный hard-бонус`.
- За правильный обычный easy/medium/hard-вопрос начисляется 100/200/300 очков. За правильный принятый рискованный вопрос начисляется утроенная стоимость: 300/600/900. Счёт может быть отрицательным.
- Перед обычным вопросом игрок выбирает одну из трёх тем. Перед рискованным вопросом интерфейс до решения ясно сообщает, что тема будет выбрана случайно, правильный ответ даст `x3`, а отказ немедленно продолжит цикл и отнимет базовую стоимость текущей сложности: −100/−200/−300. Отказ не создаёт вопрос, не снимает жизнь и не расходует время.
- Рискованный выбор использует ту же горизонтальную модель управления, что и обычное меню: `A/D` или `←/→` перемещают курсор между «Принять риск» и «Отказаться», `Enter` или `Space` подтверждают выделенный вариант. Pointer и геймпад повторяют эти семантические действия.
- На финальных экранах соло `Enter` сохраняет заполненное имя, а после записи `Enter` или `Space` возвращают игрока в главное меню; доступный геймпад подтверждает эти действия кнопкой `A`.
- Случайность выбора тем, вопросов и позиций ответов использует явный seed и воспроизводимый генератор; отказ не раскрывает и не расходует будущую бонусную тему.

## Выбор темы

- Перед обычным вопросом одна из команд получает право выбрать тему из трёх показанных вариантов.
- Три карточки обычных тем образуют горизонтальный список: `влево/вправо` перемещают курсор, `вниз` окончательно выбирает тему. На геймпаде используются те же направления D-pad, для клавиатурных схем — A/D/S или соответствующие стрелки. `Вверх` на этом экране не создаёт игрового действия; на карточках показываются актуальные подсказки назначенной схемы.
- После выбора обычной темы или определения бонусной темы появляется отдельный экран с её названием и трёхсекундным отсчётом. Вопрос и его базовый таймер начинаются только после окончания отсчёта либо нового допустимого нажатия после отпускания клавиши выбора или запрета. В сетевой игре ведущий может пропустить этот отсчёт касанием любой части своего мобильного экрана.
- Подготовительный экран применяется к обычной и бонусной теме. Финальный тай-брейк не получает дополнительную перебивку.
- Первую выбирающую команду определяет воспроизводимая seeded-случайность, затем право выбора передаётся по циклу. Если число выборов невозможно распределить поровну, разница между командами не превышает одного выбора.
- Выбранная тема определяет общий вопрос, на который отвечают все команды.
- Для бонусного вопроса показывается на одну тему больше, чем участвующих команд: 3 темы для двух команд, 4 для трёх и 5 для четырёх.
- Каждая команда публично отмечает одну тему, которую хочет исключить. Все видят текущие запреты и их командную принадлежность.
- Команда может менять свой запрет. Временное совпадение запретов разных команд допустимо, но бонусный вопрос не начинается, пока каждая команда не выбрала отдельную тему.
- Когда у всех команд выбраны разные темы, единственная незапрещённая тема автоматически становится темой бонусного вопроса и открывается экран её подтверждения.
- Горизонтальный список из 3–5 тем управляется согласно расположению карточек: `влево/вправо` перемещают командный курсор, `вниз` выбирает или заменяет запрет, `вверх` снимает запрет. На геймпаде используются те же направления D-pad, для клавиатурных схем — A/D/S/W или соответствующие стрелки. На экране всегда показываются актуальные подсказки управления.

## Ответ на вопрос

- В шапке каждого вопроса после счётчика в скобках показывается назначенная сложность: «Лёгкий», «Средний» или «Сложный». В добровольной форме жалобы показывается та же сложность оцениваемого вопроса. Маркировка только информирует игроков и не меняет правила, очки, таймеры, порядок игры или событие фидбэка.
- Вопрос имеет четыре варианта ответа, расположенных геометрически центрированным крестом: сверху, справа, снизу и слева. Текст каждого варианта визуально центрируется внутри своей карточки независимо от командных маркеров.
- Перед показом позиции вариантов воспроизводимо перемешиваются по seed партии, чтобы авторская позиция правильного ответа не давала подсказку.
- Каждая позиция напрямую соответствует физической клавише WASD, стрелке или позиционной кнопке на лицевой панели геймпада. Под каждым вариантом показываются компактные подсказки для всех поддерживаемых схем.
- Текущий вариант команды не подсвечивается и не раскрывается. После первого выбора на карточке команды появляется только галочка, подтверждающая регистрацию ответа.
- Пока не все команды ответили или исчерпали время, команда может заменить ответ; последняя зарегистрированная команда считается окончательной.
- Раскрытие начинается, когда каждая команда либо имеет ответ, либо потеряла право ответа из-за исчерпания времени.
- При раскрытии правильный вариант получает зелёный фон и знак правильности. Неправильные варианты, выбранные хотя бы одной командой, получают красный фон и знак ошибки.
- На вариантах появляются цветовые иконки выбравших их команд. Карточка каждой команды также показывает правильный или неправильный результат.
- Команда без выбранного ответа получает неправильный результат без привязки к конкретному варианту.
- Под вариантами на том же экране раскрытия показывается подготовленное объяснение без автоматического таймера чтения.
- Каждый из четырёх вариантов имеет отдельную краткую фактологическую справку. После раскрытия во всех режимах (classic, solo и network), на общем экране и персональных телефонах интерфейс показывает справки ко всем четырём вариантам, включая правильный и невыбранные. Неправильные справки подписаны своим вариантом и показываются один раз в порядке отображаемых вариантов; число и правильность выборов не влияют на состав справок. Во всех режимах и интерфейсах весь блок справок расположен снизу, после вопроса и вариантов ответа, на всю доступную ширину с обычным ограничением максимальной ширины; боковая раскладка справок не используется. Главная справка правильного ответа отображается прежним основным блоком explanation. Отдельная note правильного ответа не выводится. Три справки неправильных вариантов показываются карточками ниже, горизонтально при достаточной ширине и с переносом на узких экранах, без видимого общего заголовка «Справки ко всем вариантам». Карточки неправильных вариантов имеют слегка красноватый фон во всех типах матчей и интерфейсах, включая общий экран, персональные телефоны и accessibility-режимы. До общего раскрытия справки не передаются и не показываются.
- Сразу после объяснения показывается подписанная ссылка на источник вопроса. Она открывается в новой вкладке только по явному клику, не загружается автоматически и не требуется для продолжения или офлайн-игры.
- После раскрытия переход дальше требует нового нажатия после отпускания кнопок, использованных для ответа; удержанная кнопка не должна случайно пропускать следующий экран.
- После отпускания прежних кнопок новое допустимое нажатие сразу продолжает игру из раскрытия без отдельного шага «Хотите пожаловаться на вопрос?». Жалоба по желанию доступна через пункт «Пожаловаться на вопрос» в меню паузы, пока показаны раскрытые ответы. На desktop меню открывается через Esc и управляется штатной мышью, клавиатурой или геймпадом; на телефоне — существующей кнопкой «Меню». Отдельной кнопки жалобы на экране ответов нет.
- В добровольной форме жалобы используется единый общий выбор без командной принадлежности и отдельных голосов: слишком лёгкий, слишком сложный (взаимоисключающие), очевидно слабые неправильные ответы, непонятная формулировка, фактическая ошибка, неоднозначный ответ или неинтересный для викторины; непустая заметка до 500 символов достаточна без выбранной причины. Отмена и успешное локальное сохранение возвращают к раскрытым ответам того же вопроса; обычное действие продолжения затем ведёт дальше.
- Новое анонимное событие фидбэка создаётся только по явному сохранению жалобы на сыгранный обычный, бонусный или финальный вопрос. Обычное продолжение без жалобы не создаёт положительный сигнал «жалоб нет». Жалоба не влияет на очки, время, жизни, правила тай-брейка, текущую категорию или последующие вопросы. Исторические события сохраняются.
- Во всех режимах валидная жалоба сначала сохраняется в долговечной локальной очереди до HTTP-попытки, независимо от наличия интернета. Игра не ждёт серверного ответа и не показывает окно «Повторить / Пропустить». Фоновая доставка повторяется при старте, возвращении интернета и восстановлении API с прежним идентификатором и содержимым события; событие удаляется только после подтверждения записи. Ошибка сети или отказ API сохраняет жалобу локально. Очередь переживает перезапуск и обновление каталога без подмены исходного вопроса или ревизии.

## Время ответа

- Базовый таймер вопроса общий для всех команд и равен выбранным 10, 20 или 30 секундам.
- Во время ответа отсчёт отображается отдельно в карточке каждой команды: до окончания базы не ответившие команды видят одинаковый остаток базового времени, а общий таймер в шапке вопроса не показывается.
- Каждая команда имеет отдельный «Запас времени», вычисляемый только из длины партии и не редактируемый в меню:
  - 9 вопросов — 60 секунд;
  - 15 вопросов — 90 секунд;
  - 21 вопрос — 120 секунд.
- Пока идёт базовый таймер, запас команд не расходуется.
- После окончания базового таймера запас независимо уменьшается только у команд без зарегистрированного ответа.
- Во время расхода запаса карточка не ответившей команды показывает его остаток красным таймером.
- Первый зарегистрированный ответ останавливает расход запаса этой команды до конца вопроса. Последующие изменения ответа дополнительное время не расходуют.
- После первого зарегистрированного ответа таймер в карточке команды исчезает, а галочка регистрации остаётся; вне фазы ответа карточка показывает остаток запаса без таймера.
- Когда запас команды достигает нуля, текущий вопрос автоматически считается для неё проваленным.
- Если команда начинает вопрос с нулевым запасом, она может ответить только до окончания базового таймера; затем вопрос сразу считается проваленным.
- Пауза полностью замораживает базовый таймер и расход командных запасов.

### Время и жизни соло-забега

- Каждый вопрос соло-забега имеет неизменяемые 10 секунд базового времени и общий на весь забег запас 60 секунд. После окончания базы запас расходуется только пока игрок не зарегистрировал ответ; первый ответ останавливает расход на текущем вопросе.
- У игрока три жизни. Неверный ответ и отсутствие ответа при исчерпании запаса снимают ровно одну жизнь; третья ошибка завершает забег. Потерянная жизнь показывается пустым контурным сердцем.
- Пауза полностью замораживает авторитетные остатки базового времени и общего запаса соло-забега.

## Результаты и переходы

- После раскрытия обычное новое действие продолжает следующий выбор темы, результаты или тай-брейк напрямую. Добровольная жалоба доступна только через меню паузы при раскрытых ответах; отмена/локальное сохранение возвращают к тому же раскрытию, а отправка не управляет переходом.
- Отсчёт подтверждения темы является частью авторитетного состояния: пауза замораживает его, а восстановленная партия продолжает с сохранённого остатка.
- После первого и второго этапа показывается таблица результатов с командами, числом правильных и неправильных ответов и очками. Команды сортируются по очкам.
- Отсутствие ответа входит в число неправильных ответов и дополнительно показывается отдельной подстатистикой «Без ответа».
- Если после третьего этапа первое место делят несколько команд, партия продолжается дополнительными финальными вопросами до появления единственного победителя. Ничьи на втором и последующих местах не разыгрываются.

### Результаты соло-забега

- После третьей ошибки игрок вводит имя, и только после явного подтверждения локально сохраняется одна запись с именем и итоговым счётом.
- Экран результата показывает десять лучших локальных соло-результатов по убыванию счёта и текущий результат относительно них, даже если он не входит в top-10.
- В главном меню действия расположены вертикально в едином порядке: «Одиночная игра», «На одном устройстве (2–4)», «Сетевая игра (2–12)», затем продолжения сохранённых партий, настройки и «Рекорды». Оно не показывает настройки режима на одном устройстве: выбор вопросов, числа команд, времени и контроллеров открывается отдельным следующим экраном после нажатия «На одном устройстве (2–4)». Классическая командная настройка и её запуск по-прежнему скрыты на portrait-телефоне. Каждое продолжение явно называет режим: «Продолжить одиночную игру» или «Продолжить игру на одном устройстве».
- Таблица рекордов не синхронизируется, не защищена от намеренного локального редактирования и не содержит игровых ответов, аккаунтов или данных устройства.

- Перед первым финальным вопросом показывается таблица результатов основной игры с объявлением ничьей за первое место; новый ввод запускает финальную битву.
- В финальном тай-брейке участвуют только команды, делившие первое место после основного этапа. Остальные команды становятся зрителями до определения победителя.
- Тай-брейк использует сложные вопросы без выбора темы, бонусного множителя и начисления очков. Оставшийся у претендентов «Запас времени» сохраняется и продолжает действовать по обычным правилам.
- После финального вопроса:
  - если правильно ответила ровно одна команда-претендент, она становится победителем;
  - если правильно ответили несколько претендентов, только они переходят к следующему финальному вопросу;
  - если все оставшиеся претенденты ответили неправильно, их состав не меняется и задаётся следующий вопрос.
- Тай-брейк определяет только единственного победителя и не меняет исходные очки. Победитель получает 1-е место; остальные бывшие лидеры получают общее 2-е место, а уже существовавшие ничьи и номера мест ниже этой группы сохраняются.
- Пока остаются не показанные в текущей партии сложные вопросы, тай-брейк не повторяет вопросы. Если исчерпаны все доступные сложные вопросы каталога и победитель всё ещё не определён, начинается новый seeded-цикл: вопросы перемешиваются заново, первый повтор не совпадает с последним показанным вопросом, а выбор не закрепляется в одном и том же порядке между партиями.
- После определения единственного победителя показывается итоговая таблица и действия «Начать заново» и «Выйти в меню».
- После выхода из завершённой партии в главное меню кнопка восстановления или просмотра её последних результатов не показывается; она остаётся доступной только для незавершённой сохранённой партии.
- «Начать заново» запускает новую партию с теми же настройками и новым seed. Уже показанные вопросы сохраняются в локальной истории. Для изменения настроек требуется выйти в главное меню.
- В любой момент `Escape` открывает меню паузы с действиями «Продолжить», «Начать заново» и «Выйти в меню».

## Контент вопросов

- Каталог содержит не менее 100 тематик и минимум 100 вопросов в каждой; текущая ревизия включает 110 тематик, в том числе существующие 30 и десять отдельно выделенных страновых историй. Базовый пакет содержит 40 easy, 40 medium и 20 hard; тема с подтверждённым запасом независимых фактов и источников может содержать 200 вопросов с квотой 80/80/40 или 300 с квотой 120/120/60.
- Easy-вопрос проверяет широко известный взрослой аудитории факт, включая знания, распространённые внутри большой демографической или культурной группы. Он не строится на редких датах, терминологической ловушке или второстепенной детали, но его неверные варианты остаются правдоподобными и не выдают ответ абсурдностью.
- Medium-вопрос, скорее всего, решает человек, знакомый с конкретной тематикой; игрок вне темы не должен получать правильный вариант только через очевидную несостоятельность остальных.
- Hard-вопрос требует специфического знания или содержательной логики. В большинстве hard-пакета варианты дают возможность разумно сузить выбор даже без точного знания; вопросы с четырьмя неразличимыми догадками используются ограниченно.
- Все 1500 вопросов прежней ревизии сохраняют идентификаторы. Изменение уровня, грамматики или дистрактора фиксируется в воспроизводимом отчёте аудита с причиной.
- Каждый вопрос имеет четыре различных варианта, ровно один правильный ответ, основное объяснение и краткую справку для каждого варианта.
- Каждая справка относится к своему варианту ответа и содержит полезный проверенный факт. Справка правильного варианта дополняет спрашиваемый основной факт, а не повторяет только prompt/key; этот дополнительный факт может также встречаться в основном объяснении. Факты о другом варианте или только об общей экспедиции не заменяют содержательную связь с конкретным вариантом.
- Ручная калибровка `question-quality-pilot-100-human-v1` допускает для easy содержательный логический вывод через знакомую единицу измерения (пример: атмосфера → давление). Прямой и обратный вопросы одной связи (Темза–Лондон), а также проверенные человеком почти одинаковые вопросы о ядре/ДНК/хромосомах не считаются достаточным разнообразием: одна карточка заменяется независимым фактом. Если полезно объяснить неверность варианта сложно, его справка может дать самостоятельный познавательный факт о варианте; фактическая проверка этой справки сохраняется. Решения об easy/hard для отдельных вопросов и отклонённые черновики зафиксированы в отчёте калибровки и применяются к каталогу отдельным этапом с сохранением квот. Кандидаты round3 для карточек 3–6 и 13 одобрены по понятности и направлению: «группа динозавров» с ключом «Завроподы», вопрос о фёне без шинука среди вариантов, различение knowingly в модельном уголовном кодексе США и короткая ситуация о восьмисекундном контроле мяча вратарём по правилам футбола 2026/27. Для easy одобрен короткий геометрический вывод: удвоение длины и ширины прямоугольника увеличивает площадь вчетверо. Точные тексты и хеши закреплены в evidence/question-quality-pilot-100/round3; семантическая сверка соседней карточки про шинук остаётся условием последующего импорта.
- Для 1500 вопросов первой ревизии, созданных до появления справок вариантов, действует отдельный ретроспективный gate: все 4500 справок трёх неправильных вариантов проверяются поштучно на фактическую корректность, соответствие конкретному варианту и вопросу, самостоятельную познавательную ценность, нейтральность, отсутствие подсказки правильного ответа, русский язык и проверяемость авторитетным источником. Формальная непустота и общий review вопроса этот gate не заменяют.
- Объяснение даёт причину правильного ответа, краткую справку и при уместности интересный факт; его чтение должно занимать не более 30 секунд.
- Вопросы рассчитаны на взрослых эрудированных игроков, но не должны требовать узкопрофессиональных или чрезмерно специфичных знаний.
- Тематики охватывают российскую и мировую историю, культуру, географию, науку, поп-культуру, знаменитостей и другие области. Российскому контексту уделяется несколько больше внимания, не вытесняя значимые мировые факты.
- При аудите каждый вопрос отдельно проверяется на соответствие исходной тематике: проверяемый факт или навык должен иметь содержательную и объяснимую связь с названием и утверждённой областью темы. Совпадение отдельного слова, географическое упоминание или связь только в справке не заменяет эту проверку. Междисциплинарные вопросы допустимы при явной связи; спорные границы и отсутствие определённой области фиксируются для ручной калибровки. Для несоответствия сохраняются исходная тема, причина и предложение переноса, изменения формулировки или исключения; каталог меняется только в отдельно согласованном этапе. Для пилота одобрено направление переноса вопроса о годе запуска «Хаббла» из «Астрономия и космос» в «Космические полёты»; перед импортом проверяются квоты, источники, notes и повторы. Для вопроса с рекомендацией CDC о выборе напитка одобрен перенос из «Напитки мира» в «Человек и медицина» после проверки пригодности, границ целевой темы, источников, notes, квот и повторов; решение не подтверждает сам медицинский совет. Вопрос о гражданской науке остаётся в «Экология и окружающая среда» с уточнением участия добровольцев именно в мониторинге окружающей среды; точный текст и варианты проверяет редактор.
- Граница тем настольных и карточных игр: «Настольные игры» включают современные авторские настольные игры с картами (например, Love Letter), исключая шахматы, классические и коллекционные карточные игры и компьютерные игры. «Карточные игры» охватывают классические и коллекционные карточные игры, колоды, комбинации и историю; современные авторские настольные игры с картами относятся к теме настольных. При пересечении современного авторского и коллекционного признаков приоритет имеет категория коллекционных карточных игр. Love Letter остаётся в «Настольных играх». Обновление кодовой taxonomy и проверка затронутых карточек выполняются отдельным этапом; исходный snapshot пилота сохраняется.
- Первый пакет `question-quality-batch-1` реализует принятую рубрику максимум на 20 исходных карточках вместе с компенсациями уровней и тематик. Размеры тем, квоты уровней и баланс позиций ключа сохраняются. Исходная карточка про «расстегнуться» остаётся hold в evidence и удаляется из игрового каталога; слот занимает независимый проверенный факт, старый ключ не утверждается. Условный перенос CDC остаётся для следующего ограниченного пакета. Приёмка точной поставленной версии проводится общим итогом.
- Объяснение содержит от двух до четырёх предложений и ориентировочно не более 70 слов.
- Каждый вопрос содержит источник и дату фактологической проверки. Название источника и ссылка показываются после объяснения раскрытого ответа; дата проверки остаётся служебной. Вопросы о современной культуре используют явный временной контекст и не формулируются через меняющееся «на сегодняшний день».
- Вопрос и все четыре ответа проверяются как законченные конструкции или подстановки: падеж, число, род, управление, пунктуация и написание имён согласуются без грамматической подсказки к правильному варианту.
- Локальная история заданных вопросов переживает новые партии. Вопрос помечается использованным сразу при показе, независимо от ответа и последующего рестарта.
- Для каждой пары «тематика × сложность» используется отдельная сохраняемая shuffle-bag полного размера уровня: 40/40/20, 80/80/40 или 120/120/60 для easy/medium/hard. В рамках одного цикла каждый вопрос показывается ровно один раз в воспроизводимо перемешанном порядке.
- После исчерпания bag создаётся новая seeded-перестановка: она не должна полностью совпадать с предыдущей, а первый вопрос нового цикла не может быть последним вопросом предыдущего цикла.
- Внутри одной партии выбранные темы и вопросы исключаются из повторного выбора. Исключение для темы: если иначе невозможно соблюсти лимит групп, возвращается минимально необходимое число ранее выбранных тем с новыми доступными вопросами. Возвращение темы не сбрасывает историю сыгранных вопросов; существующие отдельные правила полного исчерпания вопросов сохраняются. Показанные, но не выбранные темы имеют пониженный приоритет.
- Каждая тема принадлежит одной из существующих 13 явных валидируемых областей taxonomy; эти области служат группами для выбора. Профиль разнообразия `topic-diversity-v1` применяется к solo, classic, network и финальному выбору: обычный и финальный набор — не более одной темы группы; бонусный набор из 3 тем — не более одной, из 4–5 тем — не более двух. При возможности группы всех карточек различаются; повтор группы в большом бонусе допустим только при нехватке разных доступных групп. Лимит относится к одному набору, а не к соседним вопросам. В одном наборе topicId уникален; равноприоритетные варианты воспроизводимы от seed. При истинном исчерпании лимит не ослабляется молча.
- История вопросов хранит только компактные сведения, необходимые для частоты и давности повторов, а не полные результаты прошлых партий.
- В настройках доступен отдельный сброс истории вопросов с явным подтверждением; сохранённая незавершённая партия этим действием не удаляется.
- Каждый вопрос имеет минимум один проверяемый авторитетный источник. После подготовки каждый пакет проходит отдельную редакторскую проверку другим агентом по фактологии, индексу ответа, уровню, дистракторам, справкам вариантов, русской грамматике и дублям до интеграции.
- Оценки assigned/perceived difficulty используются только как редакторский сигнал. Одиночный голос не переносит вопрос автоматически; отчёт показывает объём выборки и силу расхождения, а итоговый уровень всегда подтверждается ручным аудитом.

- Инициатива `catalog-question-quality` охватывает все 11 000 вопросов и 110 тем: общий поиск дефектов prompt/key/answer/note/explanation формирует проверяемую очередь точных и смысловых повторов, утечек ключа, пересекающихся ответов и несоответствия теме; автоматический scan не подтверждает фактическую истинность. Полная редактура проводится волнами по 5 тем / 500 вопросов с поштучной проверкой ключа, четырёх notes, explanation и содержательных passages реально прочитанных источников, затем независимой редакторской проверкой и отдельной поставкой. Состав каждой следующей волны фиксируется отдельным change по актуальной очереди; четвёртая технически поставленная волна — food-ingredients, computers-internet, world-exploration, history-italy, world-cinema; пятая волна (chemistry, television-media, energy-power, countries-flags, opera-musical-theatre) возобновлена 2026-10-03 по команде пользователя «продолжи улучшение вопросов по плану»; production для этого продолжения не разрешён; исправляется весь найденный объём, квоты сложности, размеры тем и позиции ключа сохраняются проверяемыми компенсациями, внешние компенсации считаются отдельно. CDC проверяется отдельно через suitability/source/target-boundary/notes/quota/repeat gate; разрешённое направление переноса не подтверждает совет.
- На 2026-09-29 завершены четыре волны полной проверки: 20 тем / 2000 карточек. Остались 90 тем / 9000 карточек до полной тематической проверки; 12 из них отдельно проверены в пилоте (ещё 8 пилотных входят в четыре волны). Точные списки, хеши и статус продолжения сохраняются в main: `docs/content-audits/question-quality-status.md` и `.json`. Дальнейшая редактура приостановлена, продолжение — отдельная будущая задача. Пользователь явно разрешил разовую поставку всех текущих обновлений main на production; это не ручная приёмка отчётов.
- Цель инициативы — актуальный результат полной проверки каждой карточки: неподтверждённые ключи исключаются из игры с сохранением исходников в hold, независимые замены проверяются полностью. Покрытие измеряется полностью проверенными карточками и темами, исправленными и открытыми дефектами, holds и очередью повторов. Исторические approved reviews сохраняют историю и не служат новым сертификатом; новые результаты связываются с хешами точных карточек и отдельно проверенными полями. Качество всего каталога не экстраполируется из пилота. Сложность редакторская до отдельной телеметрической калибровки. Приёмка каждой итоговой волны — явное общее решение человека по отчёту и показательным примерам; production deploy требует отдельного разрешения.

## Сессия и управление

- Все команды играют в одной комнате на одном общем экране.
- Каждой команде назначается уникальная схема: WASD, стрелки или отдельный геймпад.
- В селекторах контроллеров клавиатурные схемы подписываются компактно как `WASD` и `Стрелки`, чтобы название не обрезалось на командных карточках.
- Физический ввод преобразуется в семантические игровые действия единым слоем; право команды на действие проверяет игровое ядро.
- На общем экране жалобы любой назначенный источник управляет единственным общим курсором; первое валидное действие input frame после neutral gate определяет следующий шаг, остальные действия этого frame не создают отдельного результата. `Space` для WASD и правый `Shift` для стрелок подтверждают текущий пункт или продолжают экран с приглашением к новому нажатию.
- Устные обсуждения разрешены. Текущий выбор ответа скрывается интерфейсом, но приложение не обеспечивает и не пытается регулировать приватность разговоров внутри команды.
- Потеря фокуса окна или отключение назначенного геймпада автоматически ставит партию на паузу и указывает затронутую команду.
- На паузе новый или переподключённый геймпад можно назначить затронутой команде нажатием кнопки. Одно физическое устройство нельзя назначить нескольким командам.
- Прототип поддерживает стандартные раскладки Xbox, PlayStation и Nintendo. Для неизвестной модели используются универсальные позиционные глифы.
- Все командные маркеры имеют единый ромбовидный силуэт, цвет своей команды и кириллическую букву `З`, `С`, `Ж` или `К`. Глифы клавиш и кнопок геймпада используют визуально отдельную систему и не должны восприниматься как командные ромбы.
- Игра автоматически сохраняет только один снимок последней партии и перезаписывает его новыми состояниями. Снимок включает назначения контроллеров, необходимые для продолжения; архив предыдущих партий не ведётся.
- После перезапуска приложение предлагает продолжить незавершённую партию из состояния паузы либо открыть итоговую таблицу последней завершённой партии. Старт следующей партии заменяет сохранённый снимок.
- Незавершённый соло-забег использует тот же единственный механизм восстановления с сериализуемыми seed, слотами, жизнями и остатками часов. Локальная таблица рекордов хранится отдельно от снимка и истории повторов.

## Визуальное направление

- Главное меню показывает Mindbattle один раз и слоган «Все решит эрудиция»; декоративный футер отсутствует. Режимы открываются прямыми кнопками. Desktop показывает solo, classic setup и network entry; установленная игра также «Выход из игры». На телефоне solo, каталог сетевых игр, рекорды и настройки представлены компактными полноширинными кнопками одного стиля. Рекорды имеют подпись «Лучшие результаты одиночной игры». Восстановление сохранённой партии остаётся доступным.

- Игра оформляется как современная интеллектуальная телеарена без прямого копирования существующих телевизионных викторин.
- Основной фон — тёмный сине-графитовый со сдержанным сценическим свечением. Крупный светлый текст и контрастные карточки обеспечивают чтение с общего экрана. Выбрано направление «Телеарена»: ледяные акценты, тонкие границы, спокойные поверхности и единая типографика во всех меню, solo/classic/network, раскрытии, фидбэке и результатах. Сценическая сфера используется только в главном меню; игровые экраны сохраняют спокойный фон и прежнюю семантику цветов.
- Иконка приложения — светлая шахматная фигура коня из соединённых violet-узлов на тёмной скруглённой плитке. Dev-сборка использует ту же иконку с отчётливой жёлтой рамкой по периметру, чтобы не путаться с обычной сборкой.
- Вопрос и четыре варианта являются главным визуальным центром. Командные карточки и ромбы располагаются по краям и не конкурируют с содержанием вопроса.
- Справка правильного ответа образует прежний основной блок explanation; три неправильные справки образуют адаптивный горизонтальный ряд карточек ниже без видимого общего заголовка, не повторяются для нескольких игроков, равномерно заполняют доступную ширину без пустой колонки и сохраняют читаемость всех четырёх справок на поддерживаемых viewport и accessibility-режимах.
- Заголовки используют выразительный геометрический характер, основной текст — спокойный, нейтральный и хорошо читаемый. Шрифты поставляются локально вместе с приложением.
- Сильная анимация резервируется для бонусного вопроса, раскрытия ответа и объявления победителя. Остальные переходы сдержанны; постоянные декоративные частицы не используются.
- Аудиообраз телеарены использует четыре выбранные локальные композиции `quiz-v1`: отдельную тему меню и три темы этапов — очень спокойную, собранную с умеренным пульсом и напряжённую финальную. В классической и сетевой игре музыка меняется между тремя этапами партии 9/15/21 вопрос; тай-брейк сохраняет третью тему. В соло используется спокойная тема до завершения бонусного вопроса слота 4; на границе следующего слота 5 включается вторая тема. После завершения бонусного вопроса слота 14, на границе слота 15, включается третья тема и остаётся до конца забега. Отказ от риска в бонусных слотах не считается завершением вопроса; бонус слота 9 не меняет тему. Музыкальная веха сохраняется и восстанавливается с забегом. Во время вопроса тема этапа приглушается; между вопросами одного этапа не запускается заново. Pause/mute останавливают музыку; resume/unmute восстанавливают подходящую текущему экрану тему. После визуального раскрытия звучат существующие сигналы общего/частичного успеха и отсутствия верных ответов; бонус звучит поверх темы, победа заменяет её.
- Эффекты используют выбранную электронную арену `quiz-sfx-v1`: нейтральная фиксация принятого ответа, различные исходы соло правильно/ошибка/тайм-аут; общий командный экран сохраняет все правильно/смешанный результат/никто не угадал, а при отсутствии всех ответов выделяет тайм-аут. Старт, отсчёт, последние секунды, резерв, бонус и победа образуют одну палитру. Победа относится к эффектам; эффекты останавливаются на pause/mute и не повторяются на resume/restore. Темы музыки и её прогрессия сохраняются. Выбор направления 2 от 2026-10-03 не заменяет ручную приёмку игрового микса.
- Короткие сигналы перехода, отсчёта, начала вопроса, последних секунд, резерва и фиксации ответа используют записанные фактуры той же электронной арены вместо прежних синтезированных импульсов. Их назначение и длительности сохраняются; набор принят пользователем и опубликован 2026-10-07 из версии `83ef22e`.
- Основная композиция рассчитана на 16:9 и должна сохранять читаемость от 1280×720 до 1920×1080.
- На portrait-телефоне шириной 360–760 CSS-пикселей соло-композиция сохраняет вопрос, четыре позиционных ответа, счёт, жизни и авторитетный таймер без горизонтальной прокрутки; каждый вариант ответа идёт отдельной полноширинной pointer-кнопкой по доступной ширине экрана и имеет область не менее 44×44 CSS-пикселей. Классическая командная настройка в этом mobile UI не отображается, но остаётся доступной на desktop.
- Интерфейс не должен выглядеть как корпоративный dashboard: визуальная иерархия строится вокруг текущего игрового действия, а не сетки равнозначных панелей.

## Звук и доступность

- Короткий невербальный сигнал сопровождает каждую отображаемую цифру трёхсекундного отсчёта темы; отдельные сигналы обозначают начало вопроса, каждую из последних пяти отображаемых секунд базового таймера, переход к расходу «Запаса времени», раскрытие, бонусный вопрос и объявление победителя. Каждый сигнал относится только к наблюдаемому состоянию интерфейса и не влияет на правила, время или доступные действия.
- Локальные темы главного меню и игрового flow могут управляемо повторяться; игровая тема приглушается, но не прекращается при переходе к вопросу. Короткие мелодии общего, частичного и нулевого успеха запускаются только после визуального раскрытия ответа. Локальные перебивки сопровождают переходы экранов; бонус и победа сохраняют отдельные акценты. Палитра доступна в classic и solo, включая mobile solo; в сетевой партии она звучит только на общем display, но не на персональных телефонах игроков. Озвучка текста не входит в первый прототип.
- Все меню используют общие React-компоненты шапки, кнопок, диалогов и настроек с параметрами режима. «Назад» возвращает на один уровень; на входе в сетевой режим возвращает в главное меню. В игре любого режима есть «Меню»: локально оно открывает паузу; в сети ведущий управляет общей паузой, остальные открывают локальное меню без новых полномочий. Настройки возвращают в исходное меню; выход ведущего завершает комнату через существующую команду, выход остальных сохраняет возможность переподключения. Игровые действия тем и ответов сохраняют специализированное представление.
- В настройках доступны отдельные сохраняемые уровни громкости музыки и эффектов и общий mute; старое сохранённое значение общей громкости применяется к обеим категориям. Главное меню и общий экран сетевой игры не содержат отдельного переключателя в шапке; расширенные настройки открываются отдельным подменю главного меню, а во время любой партии — через pause-меню `Escape`. Во всех режимах pause-меню содержит переход «Настройки» и явный возврат в ту же паузу: это не меняет состояние, таймеры, seed, роли или доступные игровые действия.
- Изменение уровней громкости, accessibility-настроек или обратной связи обновляет активную аудиопалитру без перезапуска текущей темы; явное выключение звука останавливает её, а включение запускает подходящую текущему экрану тему.
- Интерфейс предлагает обычный и крупный размер текста, режим повышенного контраста и отключение необязательных анимаций.
- Отключение таймера не входит в настройки первого прототипа, поскольку меняет соревновательные правила.

## Техническая платформа

- Устанавливаемая desktop-версия для macOS и Windows содержит игру, вопросы и ассеты для первого запуска офлайн. Статистика сохраняется локально и отправляется после подключения к сети с подтверждением сервера. Первая поставка может быть без подписи сертификатами.
- Установленная игра загружает обновления содержимого в фоне. В главном меню web, мобильного браузера/PWA и desktop текстовая кнопка «Обновить» появляется только после обнаружения и загрузки новой версии; по нажатию применяет её в безопасной точке с сохранением данных. Если обновлений нет, кнопка скрыта. На готовой кнопке написано «Появилось новое обновление» и «Версия …» с номером именно загруженной версии. В интерфейсе Web и содержимого desktop показывается только номер приложения без хэша/суффикса сборки; полный идентификатор сохраняется в метаданных обновления; обновление оболочки — номер оболочки. Старый updater без метаданных показывает уведомление без выдуманного номера. Ошибка применения показывает сообщение с возможностью повтора. При уходе из главного меню загрузка не вызывает перезапуск. Старые desktop-оболочки без ручного API применяют уже найденную версию, иначе сообщают о фоновой проверке. Условный значок обновления на других безопасных экранах сохраняется; скачивание под автоматически определённую desktop ОС остаётся отдельным действием. Дистрибутивы публикуются в GitHub Releases публичного afonasev/mindbattle; лендинг ссылается на установщик своей ОС. На VPS хранится только каталог загрузок; старые файлы удаляются после проверки обоих GitHub assets по размеру и SHA-256. Сборка установщиков запускается отдельно при больших изменениях оболочки.
- Обновления оболочки загружаются и проверяются в фоне, применяются по нажатию значка в меню с перезапуском приложения по прежнему пути и сохранением данных. Нативный updater проверяет подписанное содержимое, сохраняет предыдущую оболочку и восстанавливает её, если новая не подтверждает запуск. Ручной установщик остаётся исключением при недоступном пути установки, DMG/translocation или неисправимой аварии восстановления.
- В общем футере приложения на web/mobile/PWA/desktop показываются текущая версия без хэша/суффикса сборки и дата/время её публикации. Метаданные принадлежат запущенной сборке и доступны офлайн; ожидание новой версии не меняет текущую версию в футере. Дата задаётся публикационным pipeline, а не временем обычной сборки. До публикации кандидат сообщает «Ещё не опубликована». Футер не перекрывает элементы игры.
- Windows-установщик Mindbattle-<версия>.exe использует иконку проекта и показывает создание ярлыка на общем рабочем столе и запуск вместе на последнем экране; обе галочки включены по умолчанию. Игра устанавливается для всех пользователей в Program Files/Mindbattle с UAC, без выбора режима; путь можно менять. При переустановке для всей системы сохраняются существующий путь и профиль. В защищённой папке обновление оболочки текущим helper без повышения прав может потребовать нового установщика; обновление игрового содержимого в userData сохраняется.
- Только установленная игра имеет пункт «Выход из игры» в меню и сохраняемые настройки разрешения, полноэкранного и оконного режима.

- Первый прототип создаётся на React, TypeScript и Vite. Classic-v1 запускается в актуальном desktop Chromium, а соло-забег поддерживает актуальный мобильный браузер как PWA.
- Весь текстовый и карточный интерфейс реализуется стандартными DOM и CSS. Canvas, WebGL и отдельный игровой движок не используются.
- Авторитетная state machine партии реализуется как чистый TypeScript-модуль без зависимостей от React, DOM, XState или глобального UI state manager.
- Клавиатура и геймпады поддерживаются через нативные Keyboard Events и Gamepad API; адаптер ввода преобразует физические события в семантические команды ядра.
- Контент хранится в отдельных статических JSON-файлах по одной тематике в каждом и собирается в валидируемый каталог приложения. Taxonomy-manifest задаёт допустимый размер пакета и квоту уровней; каждый вариант ответа хранит текст и краткую справку.
- Версионированный `localStorage` хранит только настройки доступности, назначения контроллеров, историю повторов и один снимок последней партии с восстановлением после повреждённых или устаревших данных. Контекст добровольной формы относится к раскрытому вопросу; сохранённые жалобы находятся в отдельной долговечной очереди с безопасным повтором доставки.
- Отдельный versioned key `localStorage` хранит только локальные соло-рекорды; при первом обновлении валидные legacy-записи переносятся в него один раз. Повреждение снимка последней партии, настроек или истории повторов не затрагивает уже перенесённые рекорды.
- Vitest проверяет игровые правила, таймеры, планировщик вопросов и контентные валидаторы. Playwright проверяет основные браузерные сценарии; физические геймпады проверяются отдельно вручную.
- Все шрифты и ассеты поставляются локально. Node runtime по умолчанию слушает loopback, обслуживает same-origin POST API оценки сложности и дописывает минимальные идемпотентные события в конфигурируемый append-only NDJSON-файл вне web-root. Клиент не использует внешние runtime-запросы, аккаунты, персональные данные, удалённую аналитику или телеметрию.
- Событие фидбэка v3 содержит только версию схемы, идентификаторы события, партии и вопроса, ревизию каталога, назначенную сложность, признак жалобы, причины и необязательную заметку до 500 символов; сервер добавляет время записи. Ответы команд, счёт, teamId и данные устройства не сохраняются.
- Production NDJSON-журнал, его сводка и свободные заметки доступны только оператору VPS через SSH; HTTP origin не предоставляет их чтение, выгрузку или агрегирование. Воспроизводимый SSH-отчёт сохраняет исторические v3-показы/ответы «Нет» и показывает добровольные жалобы, причины, ревизии каталога и диагностические строки без заметок; отсутствие новой жалобы не считается явной положительной оценкой, число новых complaint-событий не является числом всех показов вопросов. Ответы команд используются для показа справок только в состоянии текущего раунда и не добавляются в feedback-журнал; автоматическая переклассификация остаётся отдельным будущим решением.
- В mobile solo PWA доступны только touch-действия: выбор темы, риск, ответы, фидбэк и явная кнопка «Меню». Текстовые подсказки о клавишах, включая Escape, не показываются. «Меню» сначала ставит забег на паузу, а выход подтверждается в паузном диалоге.
- После последней потерянной жизни соло сначала показывает правильный ответ и пояснение; любое касание экрана, кроме кнопки «Меню», продолжает к экрану имени, где рекорд можно сохранить или пропустить. На телефоне четыре ответа показаны широкими двухколоночными карточками.
- PWA manifest использует локальные PNG-иконки 192×192 и 512×512, а HTML отдельно объявляет локальную `apple-touch-icon` 180×180 для добавления на экран «Домой» в iPhone. Service worker кэширует shell, каталог и локальные игровые ассеты после успешного online-открытия, поэтому соло-забег и его снимок доступны офлайн. Сохранённый анонимный feedback в минимальной локальной очереди повторяется на следующем запуске или при возвращении сети и удаляется только после успешной same-origin записи; очередь не содержит ответов, счёта, teamId или данных устройства. Новая жалоба также сохраняется локально до HTTP и доставляется в фоне без обязательного окна повторной отправки.
- При каждом online-старте PWA немедленно проверяет новую версию service worker и загружает её в фоне без переустановки. В меню или после завершения забега интерфейс предлагает применить найденное обновление; активный соло-забег не перезагружается автоматически.
- Production runtime разрешает браузеру длительно кэшировать только файлы сборки с версией в имени: при повторном открытии той же версии их тело не загружается заново. HTML, service worker и остальные файлы со стабильными адресами перепроверяются при обращении; неизменённый файл может ответить без повторной передачи тела. API и политика применения обновлений PWA от этого не меняются.

### Desktop-обновления через GitHub

Обновления установленной игры и оболочки получают подписанные manifests с GitHub Pages и проверенные файлы из версионных GitHub Releases независимо от VPS. Адрес обновлений отделён от origin сетевых комнат/статистики. Сохраняются Ed25519 pin, SHA-256/размер, монотонный sequence, safe apply и last-good recovery. Desktop проверяет при старте, каждые пять минут и восстановлении сети; проверка/скачивание/ошибка показаны текстом без ручной кнопки проверки. Готовая кнопка выделена оттенком, содержит версию и дату публикации именно подготовленного обновления; legacy без даты сообщает её отсутствие. При успешной проверке без новой версии кнопка скрыта. Web/PWA по-прежнему показывает кнопку только для готового обновления. Существующим установкам нужен переходный shell через старый feed либо новый установщик с сохранением профиля; content не заменяет оболочку. Реальные сборки/публикация и Windows/macOS N→N+1 требуют отдельного шага, автоматические проверки не являются приёмкой.

## Технические и проверочные инварианты

- Локальные gates выбираются по влиянию на контракты согласно `.agents/references/qa-scope.md` в code repo: ограниченный UI smoke плюс затронутые integration tests; full обязателен при неясном влиянии, общих критических зависимостях и перед production-поставкой. Пустой, skipped или failed прогон не считается успешным. Evidence хранит точную revision, scope, количество реально выполненных тестов и время. UI snapshots не заменяют SSE/privacy integration и физическую multi-phone/gamepad приёмку. Tooling-only правки не требуют сборки или публикации игры. После Git-интеграции QA tooling допускает финализацию без deploy при явном source_only_delivery evidence о точном commit, runtime_changed=false и исходном поручении пользователя; ручная приёмка остаётся отдельной.

- Авторитетные игровые правила и состояние партии отделены от представления, UI, физического ввода, аудио и загрузки ассетов.
- Состояние правил сериализуемо. Влияющая на результат случайность использует явный seed и воспроизводимый генератор.
- Таймеры рассчитываются по монотонному времени и проверяются на граничных значениях; отображаемая анимация таймера не является источником истины.
- Правила покрываются детерминированными тестами на одинаковые входы, порядок команд, граничные таймеры, смену ответа, ничьи, невалидные действия и прерывание устройства.
- Автотесты и сборка не заменяют плейтест целевого сценария на одном экране с реальными клавиатурными схемами и физическими геймпадами.

## Сетевая игра с телефонами

Общий экран использует утверждённое оформление классического режима: тёмный фон, крест вариантов, полное объяснение с источником и тремя справками. Карточки 2–12 индивидуальных игроков расположены под игровым содержимым в адаптивных рядах; сохраняются номера, полные имена, счёт, текущее время ответа и состояния. Запас времени на сетевых карточках не показывается; на личном устройстве игрока он вынесен в отдельный заметный индикатор с подписью и крупным числом секунд. Зелёное/красное оформление результата появляется только после раскрытия ответа. Телефонное управление и доступность сохраняются. На телефоне варианты ответа состоят из одинаковой квадратной метки А/Б/В/Г (32×32 px) слева и полного текста справа; длинный текст переносится, результат после раскрытия располагается под текстом. Ширина метки не зависит от ответа.

- Отдельный режим `network-v1` поддерживает 2–12 индивидуальных игроков через интернет; один телефон соответствует одному игроку. Локальный `classic-v1` сохраняет 2–4 команды, соло не меняется.
- Desktop создаёт комнату с названием игры и необязательным паролем, без имени создателя. Экран комнаты показывает название, список игроков, удаление участника, назначение ведущего, длину 9/15/21 вопросов и базовое время 10/20/30 секунд, кнопку старта. Создатель — общий экран, не игрок; ввод и показ четырёхзначного кода заменены каталогом комнат.
- Телефон в браузере или установленной PWA выбирает комнату в каталоге, вводит имя и пароль, если он задан. Общий Wi-Fi не требуется. Создание доступно только desktop, подключение только mobile. Новые игроки входят только в лобби, максимум 12. Каталог показывает название, число игроков из 12 и замок для защищённых комнат; защищённые комнаты до старта также видны всем. После старта комната скрыта от посторонних и доступна только её действующим участникам и создателю в «Моих играх» для возврата. Пароль не даёт права входа новому участнику после старта. Закрытые комнаты не отображаются.
- Первый подключившийся становится ведущим; в лобби создатель может назначить другого. После старта только ведущий со своего телефона управляет общими переходами, жалобой, ручной паузой, перезапуском и выходом. Кнопка «Дальше» для перехода после раскрытия и результатов находится в верхней части его экрана. Выбор обычной темы доступен назначенному очередью игроку; ответы — каждому имеющему право ответа.
- Сервер владеет состоянием, seeded-случайностью, порядком команд и таймерами. Устройства отображают одну фазу партии синхронно. До раскрытия чужие ответы и правильный вариант не передаются клиентам; телефон получает собственный зарегистрированный ответ.
- Общий экран показывает вопрос, панели всех игроков, очки, персональное время и отметки регистрации; после раскрытия — выборы, объяснение и результаты всех. Между этапами и после завершения результаты показываются компактной таблицей с общей шапкой и одной строкой на игрока, без отдельных карточек и разбиения списка игроков на несколько колонок. Панели и маркеры поддерживают 12 имён без зависимости только от цвета.
- Сетевые лобби, выбор тем, отсчёт, вопрос, карточки игроков, результаты и ведущие действия используют тот же визуальный язык, компоновку стадий, материалы панелей и главные акцентные действия, что и web-режим обычной игры.
- Мобильный экран показывает вопрос, варианты, собственные очки, время и выбор. При ожидании обычной темы он показывает имя текущего выбирающего. После общего раскрытия каждый телефон показывает правильный ответ, собственный результат, имена всех игроков возле выбранных ими вариантов и основную справку правильного ответа с тремя неправильными справками в адаптивных карточках без видимого общего заголовка. Неправильные варианты, выбранные другими игроками, получают тот же маркер ошибки, что на общем экране; игрок без ответа не прикрепляется к варианту. До раскрытия чужие ответы остаются скрытыми. Между этапами, перед финальной битвой при ничьей и после завершения на каждом телефоне автоматически показывается полная компактная таблица всех игроков с общей шапкой и одной строкой на игрока: место, имя, очки, правильные ответы и суммарное число неверных (ошибки плюс ответы, не данные вовремя); отдельный столбец пропущенных ответов отсутствует; подписи статистики вынесены в шапку, длинные имена переносятся внутри своей ячейки, отдельная личная карточка на экране результатов не дублируется; своя строка выделяется, исключённые отмечаются «Выбыл». Нажатие на свою карточку по-прежнему открывает временную таблицу текущего счёта всех игроков; любой тап закрывает её. Звук воспроизводится только общим экраном.
- На сетевых экранах выбора обычной темы, бонусных запретов, ответа и общих переходов персональный статус явно различает требуемое действие и ожидание. Когда от игрока требуется действие, статус и доступное главное действие имеют более яркий акцент; когда он ждёт остальных, статус и представление недоступных действий более приглушены, сохраняя читаемость. Цвет дополняет явный текст, а не заменяет его; правильность ответов имеет отдельные маркеры. Перед бонусом участник видит «Выберите тему, которую хотите исключить», остальные — «Другие игроки исключают темы. Вы ждёте». После собственного запрета показывается выбранная тема и ожидание остальных с доступной заменой/снятием запрета; после зарегистрированного ответа — подтверждение и ожидание с сохранением разрешённой смены ответа. Статус следует серверной фазе и праву действия, в том числе для ведущего и наблюдателей финальной битвы.
- Очки, три этапа, бонус x2, запас времени, возможность сменить ответ до общего раскрытия и финальный тай-брейк наследуют classic-v1. Первый выбирающий определяется seeded-случайностью, обычные выборы идут циклически.
- Перед бонусом до четырёх ближайших активных игроков из общей очереди запрещают по одной теме. Тем на одну больше, чем участников запретов. Уже исключённые темы и имена исключивших игроков видны всем участникам на телефонах и общем экране; такие темы недоступны остальным участникам. Игрок может изменить только собственный запрет на свободную тему. Бонус не сдвигает очередь обычного выбора.
- Потеря соединения игрока замораживает всю партию, базовое время, запасы и отсчёт темы. Общий экран показывает центральную плашку и «Продолжить без <имя>». При нескольких отключениях перечисляет всех; продолжение невозможно до возврата или исключения каждого.
- До исключения игрок восстанавливается на том же телефоне в том же браузере через «Мои игры», с прежними именем, очками и ответом. Идентичность восстанавливается локальным секретом, а не совпадением имени. Возврат с другого устройства не поддерживается. После восстановления плашка пропадает, но продолжение подтверждает ведущий.
- Нажатие «Продолжить без» исключает игрока из текущей партии; повторный вход в неё запрещён. Очки остаются в результатах с пометкой «Выбыл», без участия в очереди и борьбе за победу. Если выбыл ведущий, им становится следующий активный игрок по порядку подключения.
- Исключение участника бонусных запретов перезапускает запреты для обновлённого состава на прежних темах. Если состав сократился ниже четырёх, набор тем формируется заново размером «участники + 1». Очередь обычного выбора не сдвигается.
- При сокращении до одного активного игрока партия завершается с текущими результатами из-за недостаточного состава.
- Потеря общего экрана замораживает партию до его возвращения. Обновление страницы восстанавливает комнату и права создателя. После восстановления продолжение подтверждает ведущий.
- «Сыграть ещё» у ведущего возвращает всех оставшихся в то же лобби с прежними названием, паролем, составом и настройками. Комната снова появляется в общем каталоге и допускает новых игроков до следующего старта. Новая партия получает новый seed.
- Страница выбранной игры и экран комнаты на desktop/mobile явно показывают текущего ведущего по серверному состоянию во время ожидания и партии; после назначения или передачи роли имя обновляется. До появления первого игрока показывается «Ведущий пока не выбран».
- Каталог на телефоне использует компактные строки вместо высоких карточек: название, число игроков и признак защиты сохраняют читаемость и удобную область нажатия не менее 44×44 CSS-пикселей. Число строк страницы адаптируется к доступной высоте, чтобы больше комнат помещалось без долгого листания.
- Каталог комнат, создание игры и ожидание участников оформлены в общем стиле «Телеарена»: тёмный сине-графитовый фон, ледяные акценты, тонкие границы, спокойные поверхности, локальные шрифты и общие компоненты меню. В этих экранах нет видимых браузерных или вложенных полос прокрутки, горизонтального overflow, обрезанных элементов и случайных артефактов. Длинные списки и имена остаются доступными; адаптация учитывает мобильную клавиатуру, крупный текст и повышенный контраст.
- Сетевой режим требует проверки реального сценария общего экрана и нескольких физических телефонов; автоматические клиенты не заменяют этот плейтест.

## Анонимная статистика матчей

- Настройка статистики матча берётся с устройства, на котором его создали, и относится ко всему матчу. Сетевой сервер сохраняет авторитетность статистики; участники не создают дубли и не управляют отдельными согласиями. Перевыбор ведущего сам по себе не меняет настройку статистики. Каждый сетевой игрок может независимо открыть жалобу на раскрытый вопрос из своего локального меню; форма не ставит остальных на паузу и не даёт права продолжить игру. Display не подаёт жалобы.
- Настройка «Отправлять анонимную статистику» заменяет прежний параметр сбора обратной связи и включена по умолчанию. Подпись: «Помогает улучшать вопросы и баланс игры. Без имён и данных устройства». Выключение прекращает автоматический сбор и отправку статистики; локальные рекорды сохраняются, добровольные жалобы остаются доступны независимо от переключателя. Настройка сохраняется между запусками. При выключении неотправленная статистика удаляется; уже записанная история, жалобы и локальные рекорды сохраняются. Включение действует только для новых матчей без сбора отключённого периода.
- При включённой настройке «Отправлять анонимную статистику» существующие режимы сохраняют анонимные итоги матчей и каждого раскрытого вопроса независимо от complaint feedback. Игровые правила не меняются; добровольная жалоба не добавляет ожидания feedback; сетевых await или окон отправки статистики в переходах нет.
- Единица ответа: один игрок в solo/network, одна команда в classic. Число людей внутри локальной команды неизвестно и не выводится из командных ответов. Знаменатель вопроса — участники с правом ответа на момент авторитетного раскрытия; spectators и исключённые до раскрытия не входят. Отключение само по себе сохраняет права, переподключение не создаёт наблюдения. Бонус и тай-брейк считают только допущенные единицы.
- Для вопроса сохраняются match/event ID, режим/profile, ревизия каталога, версия содержимого вопроса, назначенная сложность, тип раунда, число допущенных единиц, correct, wrong (только выбранный неверный ответ), noAnswer, timeout (подмножество noAnswer), распределение стабильных ID вариантов. В статистике wrong не включает noAnswer, хотя игровые таблицы могут включать его в ошибки. Сумма correct + wrong + noAnswer равна знаменателю.
- allCorrect требует ненулевого знаменателя и correct == eligible; noneCorrect означает correct == 0 при ненулевом знаменателе; noSelection означает correct + wrong == 0. Доля correct / eligible. Нулевой знаменатель даёт null долю и не включается в 0%/100% сводку.
- Сыгранные вопросы бесконечного solo сохраняются при каждом раскрытии; исчерпание жизней завершает забег. Каждый конечный командный матч сохраняет итог; restart/replay/закрытие комнаты записывают прерывание, незавершённые сохранённые сессии остаются resumable. Закрытие браузера не доказывает отказ от партии: последняя контрольная точка сохраняет in-progress. Явная замена партии завершает старую interrupted. Серверные комнаты после рестарта не восстанавливаются; их незакрытые контрольные точки помечаются interrupted в read-only отчёте.
- Очередь браузера переживает reload/restart, отправляет в отдельном механизме на старте, online и после задержки повтора. Очередь удаляет событие только после подтверждённой idempotent записи. Сетевые события создаёт только сервер, с собственной постоянной очередью; клиенты их не дублируют. JS полностью закрытого браузера не исполняется. Отказ/квота хранилища допускают потерю статистики, но не сбой игры; очередь и операции ограничиваются доступным диском.
- Имена, контакты, токены и seed не отправляются. Локальная/read-only сводка показывает 0% и 100% с числом наблюдений отдельно по режиму, версии вопроса и ревизии каталога; отсутствие выбранных ответов показывается отдельно. Публичный dashboard не требуется.
