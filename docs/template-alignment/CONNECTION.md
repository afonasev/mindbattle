# Подключение общих игровых шаблонов

Источник и точная ревизия: [SOURCE.json](SOURCE.json). Снимки требований, acceptance и usage сохранены в `templates/`; обновление общего main не меняет этот контракт.

Заявленные runtime: web/PWA (desktop Chromium, portrait 360–760px); Electron macOS universal Intel/Apple Silicon и Windows x64. Минимальные целевые ОС: macOS 13 Ventura и Windows 10 x64; это целевые платформы upstream Electron, фактический запуск готового пакета на минимальных версиях пока NotRun. macOS min version закреплена в packaging config. Источник платформ: https://github.com/electron/electron#platform-support. Linux desktop не заявлен. Подпись приложения/установщика: dev/test unsigned, с явным сообщением и штатной инструкцией запуска в RU/EN release notes; подписанную платформенную поставку не заявляем.

Область предпочтений — текущее устройство/браузерный профиль, общая для локальных команд. Любой участник с доступом к общему меню может менять их. Сетевой телефон меняет только свой профиль, не параметры сервера. Экранные параметры хранятся в Electron userData/display.json; остальные — mindbattle:data:v1/preferences. Обычные опции применяются и сохраняются сразу; рискованный режим — только после подтверждения за 15 секунд. Согласие на статистику хранится отдельно. Новых отложенных обычных опций нет. Сброс не меняет согласие, партии, рекорды и историю. Очистка истории — отдельное действие.

## Контракт обновления

Стабильный канал закреплён локально; GitHub API публичного afonasev/mindbattle, без токена. Один discovery на процесс после открытия окна; ETag-кеш. GitHub Releases содержит signed manifest assets (`latest.json` либо `<platform>-latest.json`) и полный набор SHA-256 objects. Draft/prerelease исключены. Минимальный kernel в новых signed shell manifests: Darwin 22.0.0 (macOS 13), Windows NT 10.0.0. Несовместимый пакет не предлагается и повторно проверяется перед применением. Неизменяемая выбранная identity — kind/sequence + подписанные bytes; shell сравнивается численно semver, content — монотонным sequence при совместимом shellMajor/bridge. Новый контент использует bridge=2 и требует оболочку ≥1.0.6; старые оболочки с bridge=1 не должны получить UI с новыми display/update API. Сначала обновляется оболочка. Разделение версий оболочки и контента показано в футере.

«Обновить» даёт согласие только выбранной версии. Отмена снимает согласие, retry не меняет цель и не вызывает discovery. Перед матчем загрузка/история отменяются, инициатор ждёт окончания операции; после возврата в меню согласованная загрузка продолжается с тем же пакетом. Готовый контент помечается для следующего запуска при обычном выходе; оболочка применяется до открытия окна при следующем запуске. «Перезапустить» применяет раньше. Выход не ждёт незавершённого скачивания.

История — до 8 последних стабильных релизов плюс установленная версия; описания из body GitHub Release, RU для текущего меню. Отсутствующий legacy changelog честно обозначается. История не меняет выбранный пакет и не загружается в матче. Новые описания RU/EN собираются из версионируемых проверенных fragments, введённых Git-коммитами после предыдущего тега соответствующего канала; для первого выпуска используется вся история. Без описаний публикация останавливается. Старые опубликованные релизы не переписываются текущей задачей.

Манифесты старого формата без product/channel у content и channel у shell остаются читаемыми только с прежним pin, фиксированным repository/objectBase и совместимой схемой. Bridge=2 не доставляется оболочкам <1.0.6. Новые публикации содержат явную identity/channel. Это совместимость установленной базы; неподписанные или чужие payload не допускаются.

## Запуск и восстановление

Web: `http://127.0.0.1:4173/?muted=1` или опубликованный URL с тем же query. Из исходников: `npm run desktop:start -- -muted`; прежний `--muted` — совместимый alias. Установленная macOS: `/Applications/Mindbattle.app/Contents/MacOS/Mindbattle -muted`. Windows PowerShell: `& 'C:\Program Files\Mindbattle\Mindbattle.exe' -muted`. Аргументы передаются при обновлении; сохранённые громкости не меняются.

Временные downloads и журналы — userData/content и userData/shell. Для shell готовится отдельный candidate в userData, затем проверенный payload копируется рядом с установленной игрой и заменяет её только после остановки старого процесса. При нехватке прав UAC/системное подтверждение macOS получает только файловый helper; broker и новая игра остаются обычными процессами пользователя. Только signed files candidate допускаются в защищённый каталог; installer extras берутся из прежней установки. Helper подтверждает startup по token/ACK после загрузки React; при ошибке/timeout восстанавливает backup. Высокий sequence исключает автоматический цикл того же плохого релиза; следующая попытка с новым релизом при новом запуске. Формат данных v1 не меняется; masterVolume/showFps аддитивны, legacy muted мигрирует в master=0. Старый runtime игнорирует новые поля; для master=0 записывается совместимое legacy muted=true (новый UI не показывает этот технический ключ), поэтому откат сохраняет тишину. Пользовательские данные не удаляются.

При потере питания во время native swap не удаляйте `.backup-<token>` рядом с игрой или userData/shell/transactions/<token>. Если обычная точка запуска недоступна, восстановите прежний каталог из этого backup или переустановите прежний GitHub-пакет поверх установки с сохранением userData. Установку не считать успешной без ACK. Проверка этого аварийного восстановления на реальной ОС пока NotRun.

## Проверки и ограничения

Автоматические тесты и снимки перечислены в planning change `align-game-feature-templates`. Они не являются проверкой реальных UAC/macOS authorization, установщика, полного N→N+1 на обеих ОС, power-loss или физического gamepad. Сборки поставки/публикации в текущей задаче не выполняются без отдельной команды. Полный регресс игры не запускался.
