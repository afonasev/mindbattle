# Требования к обновлениям

Пакет: `updates`, версия **0.2.0**. Зависимости: `installer 0.1.0`, `menu-base 0.1.0`. Зависимости от `settings` нет.

### UPDATES-SOURCE-01 — GitHub Releases

Репозиторий релизов игры задаётся проектом. GitHub Releases хранит опубликованные версии, описание изменений, метаданные и пакеты. Проверка наличия обновления выполняется через GitHub API; отдельный сервер проверки не требуется. Публичная игра получает публичные релизы без GitHub-аккаунта игрока и встроенного общего секретного токена.

### UPDATES-SELECT-01 — Подходящая версия

Кандидат новее установленной версии, относится к этой игре и выбранному каналу, содержит полный пакет для текущих ОС/архитектуры и совместим с установленными приложением и обновляющим компонентом. Draft исключаются; prerelease не предлагается стабильному каналу.

Схема версионирования задана проектом. Сравнение не строковое и не только по дате публикации; метка GitHub latest сама по себе не доказывает пригодность. Канал закреплён локальной поставкой и не меняется командой удалённых метаданных. Автоматического downgrade нет; восстановление предыдущей версии — отдельная операция.

### UPDATES-CHECK-01 — Проверка только при запуске

Проверка выполняется автоматически один раз при запуске игры, в фоне и без задержки открытия меню. Ручного действия «Проверить обновления» нет. Повторных проверок и повторных запросов на обнаружение новой версии в течение игровой сессии нет, включая возврат в главное меню. Экраны используют общий результат стартовой проверки. Технически необходимые страницы/метаданные одной стартовой проверки не превращаются в периодический опрос. Скачивание уже выбранного пакета и получение истории изменений не являются новой проверкой версии.

### UPDATES-CHECK-02 — Сеть и лимиты

Используются кеширование и соблюдение ограничений GitHub. Нет сети, GitHub недоступен или лимит исчерпан — установленная игра остаётся доступна в пределах своего обычного offline-контракта. Неудачная проверка не объявляется актуальной версией; показано «Не удалось проверить». Ни ручного, ни фонового повторения проверки в этой сессии нет; следующая проверка выполняется при следующем запуске. Повтор скачивания ранее выбранного пакета не запускает проверку новых версий.

### UPDATES-CONSENT-01 — Фиксированное поведение без настроек

Проверка автоматическая; скачивание пакета начинается только после действия «Обновить». Игрок может игнорировать новую версию без таймера, принудительного обновления или запрета запуска установленной игры. Пользовательских настроек автообновления, канала или частоты проверок нет.

После принятого действия автоматизированы загрузка, проверка и подготовка; готовый пакет применяется при обычном закрытии игры либо до следующего запуска. Состояние готовности объясняет этот момент применения. Действие «Перезапустить» позволяет применить пакет раньше через корректное завершение приложения. Проверка наличия версии сама по себе не даёт согласия на скачивание или установку.

### UPDATES-FLOW-01 — Игра и несохранённая работа

Обновление не прерывает матч, редактор или лабораторию и не обходит обычный механизм сохранения/отмены выхода. Работающие файлы приложения не заменяются до завершения соответствующих процессов. Игрок может продолжить играть после подготовки пакета. Во время матча ничего не скачивается для обновления, включая пакеты и историю изменений. Если игрок начинает матч при незавершённой загрузке, скачивание приостанавливается до начала матча; после возвращения в меню автоматически продолжается загрузка уже выбранного пакета без новой проверки версий. Обновляющий компонент не показывает всплывающие сообщения о загрузке поверх матча. Выход из игры не задерживается ради завершения скачивания; неполный пакет не устанавливается.

### UPDATES-UI-01 — Состояния в главном меню

Компактная область обновлений использует визуальный язык игры и правила `menu-base`. Она различает проверку, доступную версию, скачивание с прогрессом, проверку пакета, готовность и ошибку. Доступны версия кандидата, «Что нового», «Обновить», повтор загрузки и «Перезапустить» согласно состоянию; ручной проверки и её повтора нет. Во время скачивания виден прогресс и доступна отмена. Кнопка «Перезапустить» появляется только после полного скачивания и успешной проверки пакета. Состояние готовности объясняет установку после выхода из игры. Завершение фоновой операции не перехватывает фокус.

При актуальной версии область не занимает лишнее место; фактически запущенная версия доступна в информации об игре. Подсказки pad размещаются на действиях по правилам базового меню. Процент скачивания не выдаётся за завершение установки. Скачанная и подготовленная версии не подменяют показанную текущую.

### UPDATES-DOWNLOAD-01 — Отдельная подготовка

Пакет выбранного релиза скачивается в отдельную временную область, а не поверх работающей игры. Проверяются свободное место и размер. Прерванную или отменённую загрузку можно повторить; докачка и переиспользование проверенных файлов допускаются. Повторная команда не создаёт вторую операцию. Неполный или непроверенный пакет не объявляется готовым. Согласие на обновление относится к выбранной версии: обнаружение или получение сведений о другом релизе не подменяет цель скачивания без нового действия игрока.

### UPDATES-HISTORY-01 — «Что нового» на языке игры

«Что нового» открывает историю нескольких последних версий, а не только последней, с возможностью выбрать и прочитать каждую, включая установленную. Для каждой версии показаны номер, дата выпуска и описание на текущем языке меню: русском или английском. Глубину истории фиксирует проект; она включает установленную версию, даже если та не попадает в обычную выборку последних релизов.

История использует русскую или английскую часть описания соответствующего GitHub Release и внутреннюю прокручиваемую область по `menu-base`. Действие доступно в меню и при отсутствии новой версии. Получение истории по запросу допускается только вне матча, не запускает повторную проверку обновлений и не меняет выбранный пакет. При недоступности сети можно показать ранее полученную историю либо оформленное состояние недоступности без выдуманного содержания.

### UPDATES-CHANGELOG-01 — Двуязычное описание релиза

При публикации каждого релиза changelog генерируется по Git-истории относительно предыдущего релиза соответствующего канала и сохраняется в описании GitHub Release на русском и английском. Для первого релиза используется история до публикуемой ревизии. Обе языковые части описывают одинаковый набор изменений.

Это человекочитаемый набор изменений и новых возможностей, сгруппированный по категориям, например «Новое / Added», «Улучшения / Improved», «Исправления / Fixed». Пустые категории опускаются. Список коммитов, внутренние идентификаторы задач и технические подробности не заменяют описание для игрока. Текст отражает вошедшие в релиз изменения и не заявляет невыполненное или неподтверждённое. Генерация changelog является частью явно разрешённой публикации, а не разрешением публиковать релиз самостоятельно.

### UPDATES-TRUST-01 — Подлинность и целостность

Описание обновления имеет проверяемую цифровую подпись; доверенный ключ/механизм проверки задан установленным приложением. Проверяются игра, версия, канал, платформа, архитектура, совместимость, размеры и контрольные суммы файлов. Контрольная сумма не заменяет подтверждение издателя. Перед активацией повторно проверяется пригодность подготовленного пакета.

Неподписанная dev/test-поставка приложения допустима по `installer`, но это не разрешает автоматически устанавливать непроверенные обновления. Недоверенный, повреждённый или несовместимый пакет отклоняется с сохранением рабочей версии.

### UPDATES-INSTALL-01 — Целостная установка

Установка завершается целиком либо остаётся доступной предыдущая рабочая версия. Прерывание питания, нехватка места или ошибка прав не оставляют установку в неопределённом состоянии. Повышенные права запрашиваются только для необходимых операций установки; игра работает с обычными правами.

### UPDATES-INSTALL-02 — Бесшовное применение

Штатное обновление выполняется встроенным компонентом или launcher максимально бесшовно: без видимого пользователю отдельного мастера установки, ручного скачивания файла, выбора каталога или переноса приложения. При необходимости helper/installer может работать как внутренняя часть процесса без отдельного пользовательского сценария установки.

«Перезапустить» корректно завершает игру с обычной защитой несохранённой работы, применяет подготовленный пакет и запускает новую версию через штатную точку входа. Если выход отменён, игра остаётся открытой, пакет — подготовленным. Сохраняются пользовательские данные, ярлыки и параметры запуска. После обычного выхода готовый пакет применяется при закрытии либо до следующего штатного запуска. Установка ожидает завершения использующих файлы процессов. Необходимый системный запрос прав допустим; обычный мастер установки не становится частью штатного обновления. Повторная ручная установка остаётся способом восстановления после сбоя, а не обычным шагом обновления.

### UPDATES-DATA-01 — Сохранность данных

Настройки, прогресс, рекорды и лабораторные данные сохраняются по контракту `installer`. Для изменения форматов данных определены миграция и восстановление. Откат приложения не должен молча открывать несовместимые изменённые данные; стратегия резервирования/совместимости описывается проектом.

### UPDATES-RECOVERY-01 — Возврат к рабочей версии

Предыдущая рабочая версия сохраняется до подтверждения успешного запуска новой по документированному startup-контракту. После неудачной установки или старта доступно восстановление. Не возникает бесконечного цикла установки одного проблемного релиза; способ повторной попытки после восстановления задан явно.

### UPDATES-ARGS-01 — Параметры после обновления

Launcher передаёт параметры запуска, в том числе после обновления и перезапуска. Тихий запуск сохраняет `-muted`, а для Unity также `-noaudio`, с обработкой до инициализации аудио. Предпочтения и системный звук не меняются. Применяются правила INSTALLER-ARGS-01.

### UPDATES-RELEASE-01 — Полный и неизменяемый выпуск

Кандидат допускается только при полном наборе необходимых файлов. Выпуск содержит версию, канал, описание изменений, пакеты и подписанные метаданные по [release-format.md](release-format.md). Выпущенная версия не подменяется другими байтами; исправление получает новую версию. Дифференциальные пакеты допускаются при наличии полного пакета для восстановления.

Если оболочка и игровой контент обновляются отдельно, их версии и совместимость определены явно. Обновление контента не объявляется обновлением всего приложения.

### UPDATES-QA-01 — Приёмка и публикация

Выбираются проверки затронутых контрактов относительно baseline. Прежние результаты незатронутых сценариев можно использовать повторно; платформенные проверки может выполнить пользователь. Ожидающие проверки не объявляются пройденными.

Применяются INSTALLER-QA-01 и INSTALLER-RELEASE-01: изменения последней версии `main` считаются проверенными, полный регресс всех тестов приложения не требуется ради публикации и запускается лишь по отдельной команде. Публикация игры/релиза требует самостоятельной явной команды человека. Автоматические запуски, включая проверку установки новой версии, выполняются без звука с самого старта.
