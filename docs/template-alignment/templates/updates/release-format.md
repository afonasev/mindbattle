# Контракт релиза

Версия: **0.2.0**. Уточняет UPDATES-SELECT-01, UPDATES-TRUST-01 и UPDATES-RELEASE-01.

GitHub Release хранит описание и assets. Схема файла метаданных определяется проектом: пакет задаёт обязательный смысл полей, а не фиксирует JSON или конкретный updater.

| Данные | Назначение |
|---|---|
| Идентификатор игры | Исключить чужой пакет |
| Версия и схема сравнения | Однозначно определить более новую версию |
| Канал | Отделить стабильные и тестовые поставки |
| Платформа, архитектура и ограничения ОС | Выбрать совместимый пакет |
| Версия схемы метаданных и требования к updater | Не активировать неподдерживаемый формат |
| Имена/идентичность assets и их привязка к релизу | Загружать файлы конкретного выбранного выпуска |
| Размеры и контрольные суммы | Проверить полное и неповреждённое содержимое |
| Цифровая подпись описания | Проверить издателя через заранее установленное доверие |
| Описание изменений RU/EN в body GitHub Release | Сгенерированное по Git-истории и сгруппированное описание для игрока, показанное на языке меню |
| Требования совместимости компонентов/данных | Определить допустимость установки и восстановления |

Описание и файлы согласованы по версии/платформе/каналу. Релиз подготавливается полностью до допуска в обновление. Пустой tag, draft, неполный набор файлов или только исходники не являются готовым пакетом игры.

Доверенные repository/channel и способ проверки подписи задаются поставкой. Удалённый файл не может сам назначить себе новый доверенный источник или отключить проверку. Пакет проверяется до готовности и перед активацией.

При нескольких компонентах отдельно фиксируются фактически запущенные версии оболочки/контента и совместимость. Для дифференциального обновления указывается подходящая базовая версия; при её отсутствии доступен полный пакет.

Ограничения API, пагинация, кеширование и retry реализуются по актуальной документации GitHub. Не предполагается, что первый релиз в ответе или `latest` автоматически подходит установленной игре.

Источники для реализации: [GitHub Releases API](https://docs.github.com/en/rest/releases/releases), [лимиты REST API](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api).

## Changelog в описании GitHub Release

Описание содержит однозначно разделённые русскую и английскую части с одинаковым смыслом. Их маркеры и формат фиксируются проектом, чтобы игра надёжно выбирала язык. Читаемый текст в GitHub Release — источник для «Что нового», а не отдельный расходящийся файл.

При публикации генератор использует Git-историю между предыдущим релизом соответствующего канала и публикуемой ревизией. Пример структуры (наполнение — реальные изменения выпуска):

```markdown
## Русский
### Новое
- <новая возможность понятным игроку языком>
### Исправления
- <исправленное поведение и его значение для игрока>

## English
### Added
- <the same new capability in English>
### Fixed
- <the same fix and its effect on the player>
```

Категории добавляются по содержанию, пустые опускаются. Автоматическая генерация не сводится к копированию commit subjects. История в меню содержит несколько последних версий и установленную, с номером/датой/локализованным описанием. Запросы истории не выполняют новое обнаружение обновлений и не скачивают данные во время матча.
