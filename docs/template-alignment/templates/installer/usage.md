# Как подключить установщик

1. Зафиксируйте `installer 0.1.0` и commit шаблонов в репозитории игры.
2. Определите поддерживаемые ОС/версии и архитектуры, форматы и имена пакетов, GitHub-репозиторий релизов.
3. Укажите стандартный каталог приложения, штатный запуск, ярлыки и единую иконку игры/установщика.
4. Опишите состав runtime-зависимостей, launcher и расположение сведений об установленной версии.
5. Зафиксируйте каталоги пользовательских данных, повторную установку, восстановление, удаление и совместную установку каналов.
6. Укажите статус поставки: подписанная либо неподписанная на стадии разработки/активного тестирования. Для второй подготовьте описание ограничений и инструкцию запуска.
7. Документируйте точную команду с `-muted`; для Unity — с `-noaudio -muted`. Проверьте передачу параметров через launcher.
8. Выберите проверки относительно baseline по [acceptance.md](acceptance.md); укажите прежние результаты и проверки, переданные пользователю.

## Пример проектного описания

```markdown
# Установщик проекта

Шаблон: installer 0.1.0, commit <ревизия>.
Релизы: https://github.com/<owner>/<game>/releases.
Платформы: <ОС/версии и архитектуры>.
Файлы: <игра>-<версия>-<ОС>-<архитектура>.<формат>.
Иконка игры и установщика: <общий исходный ассет>.
Каталог приложения: <платформенные значения>.
Точка запуска: <launcher или приложение>.
Данные пользователя: <платформенные каталоги>.
Версия и канал установки: <источник метаданных>.
Подпись: отсутствует; разработка/активное тестирование.
Ограничения и запуск: <инструкция в release notes>.
Тихий запуск Unity: "<путь к штатной точке запуска>" -noaudio -muted.
Baseline приёмки: <ветка, commit, версия пакета, платформы>.
Изменено: <diff и затронутые контракты>.
Проверки сейчас: <сценарии и команды>.
Повторно использованы: <незатронутые результаты>.
Ожидаются от пользователя: <платформы и сценарии>.
Отклонения: <согласованные исключения или нет>.
```

Шаблон не запускает сборку и публикацию автоматически. Отдельная команда человека на публикацию не означает разрешение на полный регресс всех тестов приложения.
