# Анонимная статистика матчей

Контракт утверждён в общем planning GAME_SPEC, change `persist-match-results`. Статистика независима от complaint feedback: его прежние ожидания/окно восстановления не изменены.

`npm run results:report -- /absolute/path/match-results.ndjson` читает файл без записи и без публичного API. По умолчанию `data/match-results.ndjson`; серверный путь задаётся `MINDBATTLE_RESULTS_PATH`. Рядом находится постоянная серверная очередь `.outbox`. Не публикуйте каталог data как static. Сводка диагностическая: локальные события поступают от недоверенных браузеров, это не проверенная таблица competitive рекордов.

`hundredPercent` / `zeroPercent` — группы, в которых суммарная доля правильных ответов 1 / 0. Группировка: mode + catalogRevision + questionId + questionVersion. `observations` — число раскрытий, `eligible` — сумма единиц ответа. `allCorrectObservations`, `noneCorrectObservations`, `noSelectionObservations` — число соответствующих раскрытий; последнее отдельно отличает отсутствие выбора от выбранных неверных вариантов. Нулевой знаменатель исключён из 0%/100%; его доля null. Один team answer не равен ответам каждого человека. `wrong` включает только выбранные неверные варианты, `noAnswer` — отсутствие выбора, `timeout` входит в noAnswer. В игровых таблицах `incorrect` включает noAnswer; это отдельный игровой счётчик.

Бонус и тай-брейк входят в вопросные наблюдения, но тай-брейк не добавляет очков или игровых correct/incorrect. Spectators/исключённые до раскрытия не входят в знаменатель. После раскрытия состав не переписывает событие. Переподключение не создаёт события. Версия `domain-v1-fnv64` — некриптографический fingerprint полного доменного вопроса (включая текст/варианты/correct ID/справки/источник), не доказательство подлинности. Смена только ревизии каталога также разделяет группы. Стабильные `answer-0..3` — исходные варианты до перемешивания.

`matches` содержит последнюю контрольную точку или terminal итог. Для solo score/lives; для командных режимов anonymous IDs и score/correct/incorrect/noAnswer, winner ID при завершении. Имена, контакты и capability tokens отсутствуют. `in-progress` сохраняет resumable партию; выход в меню/reload не доказывает отказ. Новый забег того же режима завершает заменённую партию как interrupted. Закрытие/replay/истечение сетевой комнаты и недостаточный состав учитываются как прерывание; серверный рестарт закрывает сохранившиеся network checkpoints. Нераскрытый отменённый вопрос не является observation. Legacy snapshot восстанавливает только сохранившийся последний reveal: прошлые вопросы не реконструируются без данных.

Браузерная очередь — IndexedDB `mindbattle-results-v1`, store `outbox`. Put и отправка выполняются асинхронно вне игрового перехода. Повтор на следующем старте, online/pageshow и таймере; запрос имеет 5 секунд timeout, ошибки дают задержку 5 секунд–5 минут с jitter. Удаление только после created/duplicate ACK с тем же eventId. Одинаковые события и replay контроллера дедуплицируются по match+round ordinal; повтор того же вопроса в другом раунде остаётся отдельным наблюдением. Сервер fsync выполняется перед ACK; torn последняя строка восстанавливается повтором из очереди. Файл с повреждённой полной строкой не переписывается автоматически.

Ограничения: полностью закрытый браузер ничего не исполняет; отправка возобновляется при открытии. До commit async транзакции reload/crash может потерять новое событие. При отказе/квоте IndexedDB событие временно остаётся в памяти и повторяется, но restart может его потерять. Отказ диска сервера сохраняет очередь где возможно, без остановки игровой комнаты; crash до durable spool также может потерять событие. Очистка browser data пользователем удаляет очередь. Размер зависит от доступного диска; события не удаляются ради лимита без ACK. Серверный журнал нуждается в эксплуатации/backup, не является безлимитным хранилищем. Не заявляется исполнение закрытого браузера или абсолютная доставка при отказе локального диска.
