# Контекст текущего среза

Читай для длинной задачи, batch-работы, после первого compaction или перед handoff.

- Один согласованный change/связный проверяемый срез — одна исполнительная сессия. Follow-up оставляй в ней, пока результат не завершён; независимая фича получает новый scope. При насыщении контекста уже разрешённой незавершённой задачи создай одного заменяющего исполнителя в прежнем scope, передай ownership и прекрати работу старого. Это не расширяет полномочия; независимый новый чат требует запроса пользователя.
- После первого compaction зафиксируй scope, проверенные факты и оставшиеся gates; сократи срез до уже начатого результата, не загружай соседние пакеты. После второго заверши только текущий атомарный результат, начатые обязательные проверки, сохранение и handoff; не начинай новый batch. Более строгий preservation-only fence сохраняется; не прерывай проверку только ради счётчика.
- Активный handoff — применимая проекция существующего manifest по шаблону ниже. Не копируй историю, логи и выполненные чеклисты. Передача роли нужна при смене ownership или остановке, а не после каждой карточки. Проекция не второй реестр и не доказательство отсутствия пропущенных gates; недостающий контекст дочитай из полного источника.
- Читай только skill текущей фазы и reference по триггеру, один раз за неизменную revision. Объединяй независимые read-only вызовы; выводи сводку и нужные ошибки. При расхождении сначала установи новую revision. Полные логи/evidence остаются по ссылкам.
- Проверки повторяй после относящейся к ним правки, новой ошибки или обязательного gate. Существующие quality/release/visual/audio/device/human gates не ослабляй. Ожидание и курсоры — по [coordination.md](coordination.md); неизменившийся blocker не требует ACK или перезаписи snapshot.
- Модели и разрешённое делегирование — по [model-routing.md](model-routing.md). Не создавай подагента ради короткой сводки; при разрешённом пакете основной агент проверяет результат.
- В редакторском конвейере атомарный результат — карточка, поручение может охватывать пакет по [question-review-process.md](question-review-process.md). Следующую карточку обрабатывай при достаточном контексте и с соблюдением compaction fences. Сравнивай accepted IDs/час, uncached input/output на принятый ID, bootstrap/ожидание, compactions и передачи; форматные и содержательные возвраты отдельно. Не обещай экономию до измерения.
- Для локального плейтеста используй in-app Browser; Chrome нужен для существующей авторизации или состояния расширений. Для browser QA держи один dev-сервер/origin; где возможно, собирай DOM, screenshot и console одним вызовом. Не ослабляй approval/guardian-проверки.

Для многоэтапного игрового среза применяй [цельный игровой результат](initiative-execution.md): компактное активное состояние без вложенной истории, синхронные status/source/next, сохранение полномочий и рабочего окружения при handoff. Существующие явные session fences и специальные содержательные проверки проекта сохраняются.

## Активный handoff из существующего manifest

`python3 tools/manifest_view.py <manifest.json> <JSON-pointer> ... --compact` выводит целые поля, path + SHA256 исходника и `projectionOnly: true`, без записи. Default pretty JSON совместим; `--compact` меняет только пробелы. Превышение 16000 UTF-8 байт — ошибка без частичного stdout. Сужай pointers, сохраняя gates или точные ссылки на них.

Выбирай поля по фактической схеме. `/CURRENT /claimsOwner /currentWork /nextUntouched` у исторического exact2000 manifest — только начало, не полный handoff. Активный вход содержит:

- цель/change/scope, текущие ID, process/spec revision и frozen hashes;
- branch + SHA, факт интеграции, owner/границы записи и нужные ресурсы;
- применимые ограничения и STOP/START, compaction/preservation fences, оставшиеся budgets/attempts;
- текущие PASS/FAIL/NotRun и evidence; следующий шаг, критерий завершения и blocker.

В поручение преемнику вставь этот компактный вход и ссылки на исходники. Начни bootstrap с него и прочитай применимые правила один раз за ревизию, даже если на них ссылаются несколько документов. Полный manifest (`source.path` + `source.sha256`), ledger и историю (путь + Git SHA) открывай для конкретной сверки, при недостающем поле или по требованию действующего контракта. При READONLY ACK сверь применимые fences, budgets и права записи с исходниками перед направленным START. В активный вход включай нерешённые ошибки и ошибки применимости текущего evidence; закрытую диагностику путей/усечений/вызовов оставляй по ссылке. Исходные FAIL/NotRun и журналы сохраняются.

Проекция — вход для чтения, не replacement schema. До изменения сохранённого формата проверь consumers: pinned takeover/checkers могут требовать полный manifest, byte-exact inherited fences и hashes. Не подставляй `fields` вместо исходника; не переписывай исторические evidence/активные сессии. Действующий [ACK → START](flow/efficiency.md), session fences, exact2000/reviewer/quality и лимиты процесса сохраняются.
