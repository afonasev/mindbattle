## Context

См. мотивацию в `proposal.md`. Обычный экран тем сейчас передаёт прямое позиционное действие в авторитетное ядро, тогда как bonus-veto уже хранит и изменяет курсор. Изменение затрагивает сериализуемое состояние, слой адаптации направления и DOM-представление.

## Goals / Non-Goals

**Goals:**

- Сделать поток обычной темы эквивалентным bonus-veto: навигация курсора, затем отдельное подтверждение.
- Сохранить детерминированность, neutral gate и неизменность правил после подтверждения темы.
- Проверить браузерный путь на обеих целевых ширинах без звука и приложить скриншоты.

**Non-Goals:**

- Не менять набор тем, seeded-порядок выбирающих команд, правила бонуса, таймеры, scoring или tie-break.
- Не вводить новые layout-паттерны, аудио, сетевую синхронизацию или миграцию snapshot schema.

## Decisions

### Один авторитетный курсор обычной темы

`MatchState` хранит индекс текущей обычной темы только в фазе выбора; он создаётся вместе со списком тем и участвует в существующей сериализации. Это отделяет правила от renderer и делает восстановление партии воспроизводимым. Альтернатива — держать курсор только в UI — отклонена, поскольку подтверждаемая тема тогда зависела бы от неавторитетного состояния.

### Разделить перемещение и подтверждение командами ядра

Левое/правое направления создают команду перемещения курсора, вниз — команду фиксации. Ядро принимает их только от текущей выбирающей команды и игнорирует вверх/прочие невалидные действия. Альтернатива — оставить одну команду выбора с индексом из UI — отклонена: она возвращает различие с bonus-veto и позволяет UI обходить авторитетный курсор.

### Переиспользовать визуальный язык bonus-veto без слияния состояний

Обычный экран показывает один публичный курсор и подсказки `←/→` + `↓`; bonus-veto сохраняет отдельные курсоры и запреты команд. Альтернатива — общий компонент с общей моделью запрета — отклонена, потому что правила участников и подтверждения различаются.

## Risks / Trade-offs

- [Старый snapshot не содержит курсор] → инициализировать детерминированный начальный курсор при восстановлении допустимого состояния либо отклонять только несовместимый snapshot через существующую версионную валидацию; решение уточняется по фактической схеме без изменения публичного контракта.
- [Удержанное подтверждение может пройти на следующий экран] → сохранить rising-edge и neutral gate, добавить browser-сценарий удержания `вниз`.
- [Курсор неочевиден визуально] → проверить DOM-состояние и снимки 1280×720 и 1920×1080.

## Migration Plan

Изменение выпускается вместе с обновлением state serialization и validator. Старый snapshot при несовместимости безопасно игнорируется по существующему правилу повреждённых/устаревших данных; откат возвращает прежнюю реализацию и тот же safe-ignore путь.
