## Context

Текущий taxonomy-manifest описывает границы тем текстом, а планировщик ранжирует допустимые темы только по частоте показа и seeded tie-break. Поэтому правило сходства не может быть проверено машинно. Выбранная тема и random-state принадлежат сериализуемой игровой логике; DOM главного меню остаётся presentation-only.

## Goals / Non-Goals

**Goals:**

- Ввести конечную область темы в taxonomy и валидировать её полноту.
- Сохранить один воспроизводимый источник случайности, применив области как приоритет до tie-break.
- Покрыть обычный и бонусный наборы, включая край нехватки областей.
- Убрать у пункта local режима отдельный primary-вес без изменения маршрута, доступности или mobile-visibility.

**Non-Goals:**

- Не менять состав каталога, тексты тем, баланс, очки, таймеры или порядок команд.
- Не выводить область игрокам и не делать персональных рекомендаций.
- Не менять API/протокол network-v1.

## Decisions

- **Явная конечная область в manifest.** Каждая тема получает одну область из общего union-типа; проверка не выводит её из `scope`. Это делает правило редакционно обозримым и не зависит от эвристики названий. Альтернатива — сопоставлять по префиксам ID или тексту `scope`; она неустойчива и не покрывает содержательное сходство.
- **Лексикографическое ранжирование.** Сначала выбирается кандидат из ещё не представленной области, затем — с меньшим `shownCount`, и только затем seeded tie-break. Когда все доступные области уже представлены, цикл начинает следующую волну. Это даёт максимум уникальных областей, сохраняет защиту от повторов и расход seeded-random предсказуемо. Альтернатива — повторять выбор до удачи; она допускает неограниченные попытки и меняет random-state.
- **Общий планировщик.** Изменение остаётся в content scheduling/context-слое, которым пользуются classic, solo и финальные списки; доменный match продолжает валидировать число и уникальность IDs, не импортируя контент или UI.
- **Вторичный стиль menu action.** Из JSX удаляется только variant, делающий classic-action primary; существующие semantic button, handler, mobile class и focus/keyboard поведение сохраняются.

## Risks / Trade-offs

- [Ошибочная редакторская классификация] → Явный список областей, полная валидация manifest и тест с историческими темами истории.
- [Разнообразие вытеснит менее показанную тему] → Область имеет приоритет только внутри одного набора; между наборами действует существующий `shownCount`.
- [Изменение порядка затронет snapshot/replay] → Зафиксировать deterministic-тесты одинакового seed/state и не менять форму сериализованного match-state.
- [Визуальная регрессия] → Добавить browser assertion классов и актуальный muted screenshot главного меню.

## Migration Plan

1. Добавить области для всего manifest и включить их в валидацию.
2. Перевести планировщик на групповой deterministic rank и добавить unit-тесты.
3. Выравнять класс local action, выполнить browser QA со звуком выключенным и сохранить screenshot.
4. При откате удалить новую классификацию и вернуть прежний ранжирующий selector; сохранённые матчи не мигрируются, так как их выбранные темы уже сериализованы.
