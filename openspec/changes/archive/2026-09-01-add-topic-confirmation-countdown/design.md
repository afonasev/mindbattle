## Context

См. `proposal.md` — Why и delta-specs. Сейчас команда `choose-topic` сразу вызывает создание `RoundState` и переводит матч в `answering`; UI запускает периодический clock только для `answering`, а input mode на остальных неинтерактивных фазах — `continue`. Snapshot уже сериализует полный `MatchState`, но валидатор перечисляет известные фазы.

Матч локальный, на одном экране, с 2–4 командами и без сети. Ведущий отсутствует; переход должен быть одинаково доступен любой назначенной клавиатурной схеме или геймпаду.

## Goals / Non-Goals

**Goals:**

- Отделить фиксацию обычной темы от начала вопроса трёхсекундной авторитетной фазой.
- Не запускать ответный таймер, не создавать вопрос и не помечать его показанным до окончания этой фазы.
- Сохранить existing neutral/rising-edge gate для выбора и ручного пропуска.
- Сделать фазу валидируемой, сохраняемой, восстанавливаемой и доступной в UI.

**Non-Goals:**

- Добавлять подготовку бонусному вопросу, tie-break или другим существующим переходам.
- Изменять выбор темы, score, reserve, random sequence, правила ответов, аудио или число фаз остального цикла.
- Разрешать pointer/touch-пропуск либо отдельную кнопку подтверждения.

## Decisions

### 1. Новая доменная фаза хранит только тему и остаток подготовки

Добавляется сериализуемая фаза наподобие `topic-confirmation` с `topicId` и `remainingMs: 3000`. `choose-topic` фиксирует тему, увеличивает ordinal и переводит матч в неё. По завершении clock либо `continue` ядро вызывает существующий выбор вопроса и создаёт `RoundState`.

Это сохраняет правило контента: вопрос отмечается использованным только когда становится видимым, а не в момент отображения названия темы. Альтернатива — создавать `RoundState` заранее и скрывать его — была отклонена: она преждевременно расходует вопрос и историю при рестарте/закрытии на перебивке.

### 2. Отсчёт использует тот же авторитетный frame clock, что и вопрос

`reduceFrame` уменьшает `remainingMs` на прошедшее монотонное время только когда матч не на паузе. При переходе остатка через ноль фаза заменяется на `answering` с полным базовым временем. Команда `continue` при активной подготовке немедленно начинает тот же вопрос; порядок команд внутри одного frame остаётся текущим детерминированным порядком, а после смены фазы дальнейшие команды этого frame не должны создать ответ.

Альтернатива с React `setTimeout` отклонена: она не сериализуема, не воспроизводима в unit-тестах и расходится с pause/restore.

### 3. Input использует существующий continue mode и neutral gate

`App` выбирает `continue` mode для `topic-confirmation`; любой actionable directional press от активного источника становится `continue`. При смене фазы input снова disarm-ится до neutral, поэтому исходное нажатие темы не пропускает экран. `Escape`, blur и gamepad disconnect сохраняют имеющееся поведение паузы.

Альтернатива с новой категорией физических кнопок отклонена: она сделала бы ранний переход разным на WASD, стрелках и геймпадах без необходимости.

### 4. Проекция и UI не получают вопрос до начала ответа

`PublicMatchView` выдаёт topic id и остаток подготовки без `question`; отдельный DOM-компонент показывает название, округлённый вверх счётчик и инструкцию. Логика polling/tick должна работать и в подготовительной фазе, но ответный audio cue и answer timer запускаются только при переходе в `answering`.

### 5. Snapshot остаётся schemaVersion 1 с расширенной строгой проверкой

Новая фаза добавляется в существующий validator без миграции: старые snapshots прежних фаз остаются валидными; новые требуют корректный topic id и `remainingMs` в диапазоне 0–3000. При повреждённом значении snapshot безопасно отвергается по текущему контракту. Восстановление добавляет pause и обновляет `lastFrameAtMs`, так что время не утекает пока игра закрыта.

## Risks / Trade-offs

- [Три секунды добавят темп партии] → только обычные темы получают перебивку, а новый ввод позволяет пропустить её раньше.
- [Удержанная клавиша проскочит сразу к вопросу] → переход фаз всегда вызывает neutral gate; проверяется для keyboard и virtual standard Gamepad.
- [Таймер начнёт расходоваться на перебивке] → доменный тест фиксирует полный `answerTimeMs` при авто- и ручном начале вопроса.
- [Повторное восстановление сдвинет отсчёт] → restore сохраняет остаток и переводит партию на паузу до явного resume.
- [Новый UI нечитабелен на общем экране] → Chromium screenshot и проверка 1280×720/1920×1080 входят в change; reduced motion не должен менять время или доступность ручного пропуска.

## Migration Plan

1. Добавить фазу, clock-переход и строгую валидацию так, чтобы старые snapshots оставались читаемыми.
2. Подключить controller, input mode и DOM-экран; сохранить существующее управление темами.
3. Добавить детерминированные и browser-проверки, обновить каноническую спецификацию и changelog.
4. При необходимости отката новая фаза перестаёт создаваться; snapshots с ней безопасно отклоняются текущим валидатором старой версии, а незавершённую партию пользователь запускает заново.
