## Context

См. proposal.md. Текущий reducer сразу заменяет третий проигранный вопрос на `finished`, а UI слушает continuation только на панели explanation.

## Goals / Non-Goals

**Goals:** сохранить финальный reveal в авторитетном сериализуемом состоянии; сделать continuation предсказуемым для touch; отделить пропуск рекорда от сохранения; изменить только presentation-геометрию карточек.

**Non-Goals:** не менять баланс, случайность, каталог, feedback или desktop classic.

## Decisions

- Добавить финальному `reveal` явный флаг завершения, а `continue` переводит его в `finished`. Это сохраняет round и result без дублирования данных; альтернатива — отдельная фаза с копией round — повышает риск рассинхронизации.
- Обработать pointer continuation на оболочке reveal и остановить всплытие у кнопок. Это даёт свободную область без превращения всех экранов в click-target.
- «Пропустить» вызывает выход в меню, не затрагивая controller storage. Альтернатива — сохранять пустое имя — нарушает требование не сохранять результат.
- На mobile заменить крестообразную сетку на две широкие колонки. Сохраняются четыре отдельные кнопки и порядок ответов.

## Risks / Trade-offs

- [Касание может попасть в вложенную интерактивную цель] → проверка target/stopPropagation и browser-тест.
- [Снимки старых забегов] → флаг финального reveal должен быть опционально мигрируемым, старые `finished` остаются читаемы.

## Migration Plan

Выполнить unit и mobile browser QA без звука; deploy остаётся отдельным явным действием. Откат — вернуть предыдущий bundle, поскольку локальные существующие records не меняются.
