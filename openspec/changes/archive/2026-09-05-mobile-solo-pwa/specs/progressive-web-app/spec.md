## Purpose

Определяет устанавливаемую PWA-версию Mindbattle с офлайн-соло, приватной очередью feedback и безопасным получением новой версии после deploy без повторной установки.

## ADDED Requirements

### Requirement: Игра устанавливается и запускает локальный соло-опыт
Поддерживаемый мобильный браузер SHALL обнаруживать manifest Mindbattle с существующей локальной иконкой и уметь установить приложение. Установленное приложение MUST запускать same-origin shell и при ранее закэшированных ресурсах позволять начать и продолжить соло-забег без сети.

#### Scenario: Установка
- **WHEN** пользователь открывает production-игру в поддерживаемом мобильном браузере
- **THEN** браузер получает manifest с названием Mindbattle, темой и локальной иконкой приложения

#### Scenario: Офлайн после первого посещения
- **WHEN** пользователь хотя бы раз успешно открыл соло-игру, затем отключил сеть и перезапустил установленное приложение
- **THEN** shell, каталог, локальные аудио и соло-снимок доступны, а игра не делает обязательный внешний runtime-запрос

### Requirement: Неотправленный feedback ожидает same-origin доставку
Когда same-origin feedback API недоступен, клиент SHALL сохранять минимальное идемпотентное feedback-событие локально и MUST не блокировать continuation соло-забега. При следующем запуске или событии `online` клиент SHALL повторить отправку по тому же same-origin API и удалить запись только после успешного ответа; очередь MUST не хранить ответы игрока, счёт, teamId или данные устройства.

#### Scenario: Фидбэк офлайн
- **WHEN** игрок подтверждает допустимый фидбэк без сети
- **THEN** забег продолжает обычный flow, а минимальное событие ожидает локальной отправки

#### Scenario: Повторная доставка
- **WHEN** ожидающее событие есть в очереди и same-origin API снова отвечает успешно
- **THEN** клиент отправляет именно сохранённый eventId и удаляет его из очереди без создания нового события

### Requirement: Новая версия применяется без переустановки и без срыва забега
После deploy service worker SHALL скачать доступную новую версию в фоне без переустановки PWA. Если соло-забег не активен, клиент MUST показать явное действие обновления; если соло-забег активен, клиент MUST отложить применение до меню либо завершения забега и не перезагружать страницу автоматически.

#### Scenario: Обновление в меню
- **WHEN** новая закэшированная версия готова, а игрок находится в меню
- **THEN** интерфейс предлагает применить обновление, и выбранное действие перезагружает приложение в новой версии

#### Scenario: Обновление во время вопроса
- **WHEN** новая версия готова во время активного соло-вопроса
- **THEN** текущий забег, его часы и состояние не прерываются, а обновление остаётся доступно в безопасной точке
