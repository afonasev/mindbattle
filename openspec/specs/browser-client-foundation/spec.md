# browser-client-foundation Specification

## Purpose

Определяет запускаемую offline-first основу Mindbattle в desktop Chromium, на которой последующие changes смогут добавлять игровые правила, ввод, контент и законченные интерфейсные состояния без смены технологической платформы.

## Requirements

### Requirement: Локальный browser-клиент запускается без backend

Система SHALL предоставлять browser-клиент, который после загрузки собственных статических ресурсов работает без backend, аккаунта, аналитики, телеметрии и runtime-сетевых запросов.

#### Scenario: Запуск локального клиента
- **WHEN** пользователь открывает клиент в поддерживаемом desktop Chromium через локальный HTTP-сервер
- **THEN** приложение отображает стартовый shell Mindbattle без обращения к внешним runtime-сервисам

#### Scenario: Production build
- **WHEN** разработчик выполняет production build
- **THEN** система создаёт самодостаточный набор статических HTML, CSS, JavaScript и локальных asset-файлов

### Requirement: Стартовый интерфейс соответствует утверждённому направлению

Клиент SHALL отображать DOM/CSS-интерфейс в направлении современной тёмной интеллектуальной телеарены и MUST сохранять читаемую композицию в диапазоне 16:9 от 1280×720 до 1920×1080.

#### Scenario: Просмотр стартового shell
- **WHEN** клиент открыт при поддерживаемом размере viewport
- **THEN** пользователь видит название Mindbattle, ясное основное действие и крупный контрастный текст без вида корпоративного dashboard

### Requirement: Основа готова к независимому расширению

Система SHALL иметь отдельные границы для доменных правил, orchestration приложения, внешних adapters, UI и контента, а доменный слой MUST импортироваться без React, DOM, audio, input и storage-зависимостей.

#### Scenario: Проверка архитектурной границы
- **WHEN** выполняется автоматическая проверка проекта
- **THEN** она подтверждает, что чистый доменный entrypoint не зависит от UI и browser adapters

### Requirement: Основа имеет воспроизводимые проверки

Проект SHALL предоставлять команды статической проверки, unit-тестов, production build и browser smoke-проверки.

#### Scenario: Полный локальный check
- **WHEN** разработчик запускает агрегированную проверочную команду на поддерживаемой версии Node.js
- **THEN** typecheck, unit-тесты и production build завершаются успешно либо возвращают ненулевой код с диагностикой

#### Scenario: Browser smoke
- **WHEN** smoke-проверка открывает собранный или локально запущенный клиент в Chromium
- **THEN** она подтверждает загрузку Mindbattle shell без необработанных ошибок страницы
